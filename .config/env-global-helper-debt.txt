# Helper-attributed env-global hazards that predate the widening of
# scripts/check-test-env-globals.py (FerroxLabs/wayland#1134 c3).
#
# ── WHY THIS FILE EXISTS ────────────────────────────────────────────────────
#
# Until 2026-08-29 the lint fired only on a `set_var` written lexically inside
# a test fn. The identical write moved one call deep -- into an RAII env guard,
# a `temp_state()`, a `stub_npm_on_path()` -- was classified `helper` and
# excused, 153 sites of it, including `PinnedRetryBudget::pin`, the helper
# #1134 opens with. Resolving callers turned that excuse into a verdict, and
# the verdict named nine pre-existing pairs on the day it was written.
#
# THE LIST IS NOW EMPTY, and that is the state the file was designed to reach.
# All nine pairs have reached a terminal state:
#
#   * Three `temp_state()` rows left when `StateDirGuard` replaced them.
#   * The `wcore-cli` row left on 2026-09-10 for a different reason worth
#     reading: it was never a hazard. `gateway.rs::run_gateway` does write
#     WAYLAND_HOME from production code, but nothing in the wcore-cli test
#     binary calls it. The "reached from an unserialized test" verdict came
#     from the caller walk following `fn run`, a name that crate declares 31
#     times, into 155 unrelated call sites. The walk now refuses a colliding
#     name at every hop rather than only the first, and the gate reports that
#     write as unattributable.
#   * The last five left on 2026-09-10 by the fix the header of this file kept
#     deferring: the helper stopped writing the process global, and the value
#     is stated at the CALL SITE instead -- the shape `ContainerBackend::
#     with_image` already used. Four seams carry it, all in production code
#     because the callers are integration tests that link these crates without
#     `cfg(test)`: `wcore_browser::liveness::BrowserProbeTarget` (the sidecar
#     URL and program), `WorkspacePolicy::with_user_config_root` (the skill
#     SOURCE roots), `SupervisorConfig::npm_program` (the npm executable, so a
#     stub no longer has to be prepended to PATH), and
#     `TelegramChannel::with_state_dir` (the offset watermark root). No
#     re-dating, no serialization, no environment write in either direction.
#
# An EMPTY list is not a dead file. Every rule below still runs on every CI
# invocation, so the next helper-attributed hazard is refused outright rather
# than added here -- which is the point: a debt list that never empties is a
# list, and this one emptied.
#
# ── WHAT A LINE HERE DOES AND DOES NOT DO ───────────────────────────────────
#
# A listed SITE is REPORTED loudly on every run and does not fail the gate.
# Everything else fails. A line is an exemption for ONE WRITE, identified by
# `<file>.rs::<writing fn>`, and NOT for the (binary, var) class it belongs to:
# a second helper writing the same variable in the same test binary is a new
# instance of the class and reds the gate with the line still sitting here.
# That is deliberate and is the thing this file got wrong first time round --
# a class-keyed exemption is a gate that cannot catch the next one.
#
# Four rules keep the list from rotting, all enforced by the gate itself and
# all proven in both directions by `--self-test`:
#
#   * A write that is DIRECT -- inside the test fn -- is never exempt,
#     whatever this file says. The exemption covers only the class the lint
#     could not previously see.
#   * A line must name a site. A line without the site column is refused as
#     unparseable rather than read as a class-wide exemption.
#   * An entry past its expiry fails exactly as an unlisted site does.
#   * An entry that no longer matches anything fails as STALE. The list is
#     designed to shrink, and a line that has quietly stopped applying is a
#     line that would excuse the next write at that site for free.
#
# ── FORMAT ──────────────────────────────────────────────────────────────────
#
#   <YYYY-MM-DD expiry>  <test-binary>  <ENV_VAR>  <file.rs::fn>  <gh#NNNN>  <reason...>
#
# Whitespace-separated; the reason is the rest of the line and is MANDATORY.
# The binary id is what the gate prints: `<crate>` for a lib test binary,
# `<crate>::<target>` for an integration one. The site is the repo-relative
# path of the file holding the `set_var` and the name of the fn it sits in,
# both of which the gate prints beside every finding. Line numbers are
# deliberately not part of the key: they drift on unrelated edits.
