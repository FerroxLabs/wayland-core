#
# `[profile.ci] retries = 2` in .config/nextest.toml means a test that fails
# twice and passes on the third attempt is reported `FLAKY 3/3` and counted in
# the PASSED total. The run conclusion — the thing release gates, dashboards
# and humans read — says SUCCESS. MEASURED consequence (#1169): the TOCTOU
# data-loss race of #1155 failed 13 of 200 runs at `--retries 0` (6.5 %), and
# 0.065^3 ~= 1 visible report in 3,600 CI runs. A defect that destroys user
# data on one edit in fifteen was invisible to CI essentially forever.
#
# `.github/scripts/grade-retry-flakes.sh` runs in the `report` job — a REQUIRED
# status context on main — over every leg's uploaded JUnit, and FAILS the run
# for each `<flakyFailure>` whose test is not listed here. Retries still run:
# the merge is not blocked by one transient network hiccup mid-suite, because
# the retry still succeeds and the suite still finishes. What changes is that
# the retry is no longer SILENT.
#
# ── WHAT A LINE HERE MEANS ─────────────────────────────────────────────────
#
# NOT "this test is fine". A line here means "this test is KNOWN to need
# retries, someone owns it, and the debt has a date on it". Every entry expires;
# an expired entry fails `report` exactly as an unlisted flake does, so the only
# ways out are fixing the test or renewing the entry deliberately with a fresh
# justification. The list is designed to shrink.
#
# DO NOT add a test here to quiet a race you have not investigated. The correct
# home for a test whose flake IS the bug under investigation is a scoped
# `retries = 0` override in .config/nextest.toml (three such blocks already
# exist, for #1109, #1101 and #1146) — that makes the failure reach the run
# conclusion directly and this gate never sees it, because a zero-retry failure
# is a plain failure, not a flake.
#
# ── FORMAT ─────────────────────────────────────────────────────────────────
#
