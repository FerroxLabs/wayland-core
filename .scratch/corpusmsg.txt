Regenerate the Desktop contract corpus after the 17-lane integration

Four lanes each touched the generated corpus, so every one of them conflicted on
merge. I resolved those with `git checkout --theirs`, which takes ONE lane's
generated output rather than the output of the merged tree - so the checked
corpus described a tree that never existed. Two tests caught it exactly as they
are meant to:

  wcore-protocol::desktop_contract_corpus::checked_corpus_matches_real_serializers_byte_for_byte
  wcore-protocol::quiescence_contract::the_published_corpus_is_current

Regenerated with `wcore-contract generate`. Seven files, and the generator
version is UNCHANGED at 22 - so this is drift from the merge, not a
Desktop-facing contract change, and Desktop's re-pin is unaffected.

Both tests pass. The rule for next time: a generated file is regenerated after a
merge, never hand-resolved and never taken from one side.
