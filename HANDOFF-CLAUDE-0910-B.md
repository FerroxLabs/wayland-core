## 7. Traps that cost real time today

* **`blocked` is NOT available to us.** The gate refuses it:
  *"Core cannot block on itself — name the lane that owes the work, or mark it
  not-met."* It needs `owner:` on another lane plus `handoff: <owner>/<repo>#<n>`
  pointing at an OPEN issue.
* **The corpus needs ONE regen over the MERGED tree.** Two lanes each touched a
  different `SOURCE_INPUTS` file (`engine.rs`, `output/protocol_sink.rs`) and each
  regenerated over its own tree; neither was current here. Order is **`cargo fmt`
  FIRST, regenerate SECOND** — `main.rs` and `engine.rs` are themselves
  SOURCE_INPUTS, so formatting them re-drifts what you just regenerated.
  **Verify `schema_digest` is an IDENTICAL SET across the diff**; only
  `fixture_digest` and `source_inputs_digest` may move. Current values:
  `schema_digest sha256:8497e92e…`, unchanged.
* **Three of the 13 required checks on `main` never run on `integ/**`** —
  `Bench regression (linux)`, `scan`, Supply Chain are all
  `on: pull_request: [main]`. **A green integ run does not predict a green PR.**
* **Meeting one criterion can orphan another.** core#434 c3 requires an allowlist
  entry DELETED; c4's evidence was anchored to text INSIDE that entry. The gate
  caught it (*"the evidence is gone, not merely moved"*). Never keep a dead
  allowlist line alive as a ledger anchor — move the record to its own file.
* **`rtk` mangles output.** Use `/usr/bin/git`, `/usr/bin/grep` directly for
  anything quoted; shell redirection can silently produce a 0-byte file.
* **`fuser -m <dir>` checks the whole MOUNT**, not the directory. It dumped every

* hetzner disk: was 60G against remote-proof's 40G floor. Reclaimed the idle push
