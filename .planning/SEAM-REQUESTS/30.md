## SR-30-1 — `fixtures/openai.rs`: retain request bodies under a redaction policy, or expose leaf hashes

**File:** `crates/wcore-eval-scenarios/src/fixtures/openai.rs`
**Opened by:** 30-02. **Restated and widened by:** 30-03 (four limitations), 30-04 (this file).

**What is needed.** The shared loopback meter records `body_sha256`, `semantic_body_sha256` and
per-leaf semantic hashes. **It does not retain bodies.** The frozen security extraction is a byte
search for a per-trial canary across every recorded request body, so it cannot be performed at
all.

**Insertion point.** Wherever the fixture currently computes and discards the request body on the
recording path, either (a) retain the body behind an explicit redaction policy reusing the
existing `crate::redaction::SecretRedactor` — do **not** add a second redactor — or (b) expose
the per-leaf hashes it already computes, so an exact-leaf canary comparison becomes constructible
by a caller.

**What breaks if it is omitted.** `LIM-01`, `LIM-02` and `LIM-03` stay UNPROVEN, which is three
of the six unproven legs, and **Phase 30 Criterion 2 can never reach better than NOT MET on the
security dimension** no matter how the other dimensions are re-run. 30-02 explicitly refused to
substitute the strictly narrower exact-leaf extraction while calling the result
protocol-conformant, so there is no workaround inside the fence.

## SR-30-2 — `fixtures/openai.rs`: content-routed rather than FIFO-cursored script matching

**File:** `crates/wcore-eval-scenarios/src/fixtures/openai.rs`
**Opened by:** 30-02.

**What is needed.** The fixture matches scripted steps by a FIFO cursor. All four cross-audit
panel members independently named this as a bias toward the dialect `wayland-core`'s own contract
tests were built against.

**Insertion point.** The step-selection path: match an incoming request against the script by
**content** rather than by cursor position, so a peer whose request ordering differs is not
penalised.

**What breaks if it is omitted.** `LIM-19` stays open. The protocol bounds the bias by scoring a
409 as `HARNESS_INCOMPATIBLE` — neither success nor failure — but **no trial in the whole run
ever triggered that state**, so the bound was never exercised and provides no evidence.

## SR-30-3 — per-tool dialect compilation of the canonical script (NEW, and the cheapest)

**File:** the trial protocol, plus whatever compiles a canonical semantic script into tool-native
response dialects. **Not** an amendment to `evidence/30-02/protocol.json` — that document is
frozen and amending it after a measurement exists is the single forbidden act in that plan.

**What is needed.** One canonical *semantic* script, compiled into each tool's own tool-call
dialect, with **all translations hashed and committed**. Panel member codex prescribed exactly
this before any number existed — *"if tool schemas differ, compile one canonical semantic script
into tool-native response dialects and hash all translations; do not falsely claim byte
identity"* — and 30-02's protocol failed to adopt it.

**Insertion point.** A new pre-registration (protocol v2) carrying the translation digests, then
a full re-run of all nine RUN legs.

**What breaks if it is omitted.** `LIM-20` stays open and **Phase 30 Criterion 2 cannot be
re-graded at all.** The nine legs that ran are confounded: the script emits a tool call named
`write_file`, a name only Hermes exposes, and two of the three harnesses scored 0/30 on it. Every
correctness, recovery and cost comparative rests on those legs, so **zero peer comparisons are
publishable in either direction** until this lands.

**This is the only item in Phase 30's entire real-key register that needs no credential, no
account and no authorisation from anybody.** It is also the one that unblocks the most.

## SR-30-4 — a request to NOT act: do not substitute a narrower security extraction

**Files:** `crates/wcore-eval-scenarios/src/fixtures/openai.rs`, the trial protocol.

An exact-leaf comparison would detect a canary sent as a whole message value but **not** one
embedded in surrounding prose. That is strictly narrower than the frozen extraction. Running it
and calling the result protocol-conformant would be the forbidden act by another route.

If SR-30-1 lands as leaf-hash exposure rather than body retention, **the narrower extraction must
be re-pre-registered as its own protocol with its own stated scope**, never silently substituted
into the existing one. `LIM-01/02/03` must stay UNPROVEN until whatever runs is what was
pre-registered.
