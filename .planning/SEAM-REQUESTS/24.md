## SEAM-24-03 — protocol events for gateway lifecycle and delivery

**Status: NOT APPLIED, and DELIBERATELY NOT DESIGNED. See below.**

### Files: `crates/wcore-protocol/src/contract/generate.rs`, `crates/wcore-protocol/contracts/desktop/v1/manifest.json`

The 24-01 plan required this executor to land every Phase-24 protocol event
in wave 1 — gateway lifecycle transitions, drain progress, active-turn
count, delivery outcome — bump the contract generator's version constants,
and regenerate the desktop manifest.

**No event shapes are proposed here, and that is a deliberate refusal.**
Filing a speculative event set for a Desktop contract, against a generator
this executor could not run end to end and a manifest whose byte-exact
regeneration could not be verified, would put unreviewed surface into a
versioned cross-repo contract. The plan's own instruction to land keys "even
where this plan does not consume them" is exactly how an unused, wrong
surface gets frozen into a manifest.

**What breaks if omitted:** the gateway's lifecycle transitions and drain
counts are not observable to a host over the protocol. The operator can read
them from `gateway status --json` once SEAM-24-01 lands; the Desktop app
cannot. Threat T-24-01-04 (repudiation of drain/upgrade transitions) is
mitigated only in the gateway's own log, not in the protocol event stream.

**Recommended disposition:** treat this as work for whoever integrates the
Phase-24 branches, once at least one consumer exists that can say what the
event needs to carry. Do not synthesise it from this document.
