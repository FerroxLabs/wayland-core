**Exact lines to add:**

```rust
// F23-02 (Phase 23B) — operator verbs over the session substrate: search,
// inspect, fork, retry, export, retain, reconcile and cancel.

```

**What breaks if omitted:** `crates/wcore-agent/src/session_lifecycle.rs` is never
compiled. `crates/wcore-cli/src/session_cmd.rs` fails to resolve
`wcore_agent::session_lifecycle`, so the whole `wcore-cli` crate fails to build and
the `wayland-core session` subcommand — every Criterion 2 verb, including the
`reconcile` and `cancel` verbs that close live Windows UAT defect D2 — does not exist
on the shipped binary.

## SR-23B-03 — `crates/wcore-cli/src/main.rs`: register the `Session` subcommand

**File:** `crates/wcore-cli/src/main.rs`

**Insertion point A** — inside `enum TopCmd` (declared at line 599 at base
`15971d1b`), as a new variant. Placed immediately before the `Swarm(...)` variant
locally; any position inside the enum is equivalent.

**Exact lines to add:**

```rust
    /// F23-02 (Phase 23B): operator verbs over saved sessions — list, search,
    /// show, fork, retry, export, retain, reconcile and cancel. Every
    /// operation prints a machine-observable `F23_SESSION=<verb>` token to
    /// STDOUT and uses the documented exit-code map in `session_cmd`.
    Session(wcore_cli::session_cmd::SessionArgs),
```

**Insertion point B** — in the `match` that dispatches `TopCmd`, alongside the other
subcommand arms (the arm for `TopCmd::Swarm(args)` is the nearest model).

**Exact lines to add:**

```rust
        Some(TopCmd::Session(args)) => {
            return wcore_cli::session_cmd::run(args);
        }
```

Note: the dispatch must occur **before** `Config::resolve`, matching the existing
`--list-sessions` short-circuit at `main.rs:1484`. Listing and searching sessions must
work without a provider API key, which is the pre-existing first-run contract; the
local edit places the arm in the same pre-resolve dispatch block.

**What breaks if omitted:** the subcommand is unreachable from the shipped binary.
`wayland-core session --help` exits non-zero, every Criterion 2 verb is unavailable to
a user, and live Windows UAT defect D2 (a crash-interrupted session is permanently
unresumable because the `reconcile` and `cancel` commands the engine's own error
message names do not exist) remains open.

## SR-23B-04 — `.planning/BACKLOG.md`: MEDIUM/LOW findings from Phase 23B

**File:** `.planning/BACKLOG.md`
**Insertion point:** append as new rows to the existing findings table.

**Exact rows to add:**

```
| 23B-M1 | MEDIUM | `wayland-core --list-sessions` prints its table to STDERR (`main.rs:1510-1525`), so a caller cannot capture it with a plain stdout redirect. The new `session list` subcommand prints to STDOUT; the older flag was deliberately left unchanged to avoid breaking any consumer parsing stderr. Consider converging them in a future minor. | Phase 23B-01 |
| 23B-M2 | MEDIUM | `session retry` re-derives approval admissibility from the durable journal's tool-effect state, not from a live re-evaluation of the current policy gate against the recorded tool intent. That is strictly conservative (it refuses more than a live re-derivation would) but it is not the full re-derivation F23-02 describes. Closing this needs the engine's policy gate reachable from a non-engine context. | Phase 23B-01 |
| 23B-M3 | MEDIUM | `ProviderAttemptFinished` / `ProviderAttemptNotStarted` (and their V2 forms) carry no `source` field, unlike `ToolExecutionResolved` which carries `ToolResolutionSource::Operator`. When an operator resolves an interrupted provider attempt through `wayland-core session reconcile --resolve`, the journal cannot record that a human rather than the engine asserted that outcome. Adding a source field is a `wcore-protocol`-adjacent journal-model change and was deliberately not attempted inside 23B. | Phase 23B-01 |
| 23B-M4 | MEDIUM | `wayland-core --session-id <id>` on an ALREADY EXISTING session fails with `Session ID '<id>' already exists` rather than resuming it; `--resume <id>` is the resuming flag. The failure mode is quiet and expensive: a script that uses `--session-id` to "continue" a session never reaches the engine's recovery gate at all, so any assertion about recovery behaviour passes vacuously. This cost 23B-01's own driver a self-passing gate before it was caught. Consider either resuming on an existing id or naming `--resume` in the error text. | Phase 23B-01 |
```

## SR-23B-05 — `.planning/BACKLOG.md`: HIGH finding 23B-H1 (journal unreadable after a clean run)

**File:** `.planning/BACKLOG.md`
**Insertion point:** append to the findings table. **This one is HIGH, not MEDIUM**, and
is filed here only because `BACKLOG.md` is fenced — it should be promoted to a tracked
issue, not left as a backlog row.

**Exact row to add:**

```
| 23B-H1 | HIGH | A cleanly-exited `wayland-core` run can write a session journal the product cannot read back. `wayland-core --resume <id>` then fails with `Error: journal checksum mismatch at sequence 16`, while `--list-sessions` still lists the session — the user sees a session they cannot re-enter, and every operator verb that reads the journal (`show`, `retry`, `export`, `reconcile`, `cancel`) fails identically, so there is no repair path. No crash or kill is involved. Measured on `hetzner-dsm` at base `15971d1b`, release binary: 8/8 and 9/10 reproductions in two bursts under concurrent compile load, 0/3 when the host was quiet — intermittent and load-sensitive. Journal size at failure ~203 KB vs ~71 KB on the passing shape. Attributed to the product, not to Phase 23B: nothing in 23B touches journal append, checksum computation or flush ordering, and the failing read is the engine's own resume path. NOT YET CONFIRMED against a pristine binary built from `15971d1b` with no phase sources applied — that is the highest-value next step. Full evidence: `.planning/phases/23B-continuous-agency/23B-01-LIVE-EVIDENCE.md` section 3. | Phase 23B-01 |
```

**What breaks if omitted:** the most serious defect this phase found is not tracked
anywhere. It is strictly worse than the live Windows UAT defect D2 that Phase 23B was
chartered to close: D2 leaves a session blocked but repairable, whereas this leaves it
permanently unreadable.

**What breaks if omitted:** two MEDIUM findings raised during 23B execution are not
tracked anywhere. Neither blocks a Success Criterion; both are real and should not be
lost.
