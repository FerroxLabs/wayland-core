## SR-23A-C1-1 — fenced file edit (`crates/wcore-cli/src/main.rs`)

**Status: NOT applied by this lane.** `main.rs` was read but not modified.

**Why it is wanted.** 23A-C1 now has a working revocation and rollback engine
(`wcore_skills::govern`) and a shipped surface (`wcore-skill-govern`). The natural home for
the verbs is beside the existing `--skills-audit` / `--skills-archive` flags, so users find
them where they already look. The separate binary is a correct interim, not the end state.

**File:** `crates/wcore-cli/src/main.rs`
**Insertion points:** two, both additive, each one contiguous block.

**(a) Flag declarations** — immediately after the existing `skills_archive` declaration:

```rust
    /// 23A-C1: revoke an auto-drafted skill. Retains every byte first, so the
    /// revocation is reversible with `--skills-rollback`. Suppresses re-drafting.
    #[arg(long, value_name = "SKILL_NAME")]
    skills_revoke: Option<String>,

    /// 23A-C1: roll a revocation back, restoring the exact prior bytes and
    /// clearing the suppression. Argument is the id printed by `--skills-revoke`.
    #[arg(long, value_name = "REVOCATION_ID")]
    skills_rollback: Option<String>,

    /// 23A-C1: list drafted skills and any revocations in force.
    #[arg(long)]
    skills_governance: bool,
```

**(b) Dispatch** — beside the existing `skills_archive` dispatch arm, delegating to the
same library the binary uses, so there is exactly one implementation:

```rust
    if let Some(name) = cli.skills_revoke.as_deref() {
        return run_skills_revoke(name).await;
    }
    if let Some(id) = cli.skills_rollback.as_deref() {
        return run_skills_rollback(id).await;
    }
    if cli.skills_governance {
        return run_skills_governance_list().await;
    }
```

The three `run_*` bodies are thin wrappers over `wcore_skills::govern::GovernanceStore`;
the logic in `crates/wcore-skills/src/bin/wcore-skill-govern.rs` transfers directly.

**What breaks if omitted:** nothing regresses, and nothing becomes unreachable — the
capability ships and is drivable via `wcore-skill-govern`. What is lost is discoverability:
a user looking for "how do I undo this" in `wayland-core --help` will not find it.

**Explicitly NOT requested: un-hiding `--skills-promote`.** It remains a `bail!` and must
remain `hide = true`. This lane did not implement governed promotion. See §"What remains".
