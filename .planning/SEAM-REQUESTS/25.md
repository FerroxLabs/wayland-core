# Seam requests — Phase 25

Three fenced-file changes are required. **All three were also made locally in this worktree**,
because without them `crates/wcore-cli` does not compile and no live proof of Criterion 1 would
have been possible. Those local edits must NOT be assumed to survive integration — apply the
requests below serially.

Everything else in Phase 25 is self-contained in new files or in unfenced files.

---

## SEAM-25-1 — `crates/wcore-cli/src/lib.rs`

**Insertion point:** end of file, after the existing `pub mod fetch;` block (currently the last
`pub mod` declaration, around line 151).

**Exact lines to add:**

```rust

// F25-01: CLI surface `wayland-core backend` — the execution-backend operator
// surface (list / probe / run / cancel / orphans / receipt verify / diff).
pub mod backend;
```

**What breaks if omitted:** `crates/wcore-cli/src/backend.rs` is never compiled into the library,
so `wcore_cli::backend::run` does not exist and `main.rs` fails to build. The entire
`wayland-core backend` operator surface disappears, and with it the only surface Success
Criterion 1's live proof is allowed to drive.

---

## SEAM-25-2 — `crates/wcore-cli/src/main.rs`, part A (the `TopCmd` enum)

**Insertion point:** inside `enum TopCmd`, immediately after the existing line
`    Fetch(wcore_cli::fetch::FetchArgs),` (around line 718).

**Exact lines to add:**

```rust
    /// F25-01: execution backends — list / probe / run / cancel / orphans /
    /// receipt verify / diff across local, container, ssh and cloud.
    Backend(wcore_cli::backend::BackendArgs),
```

**What breaks if omitted:** `wayland-core backend …` is not a recognised subcommand. clap exits
with "unrecognized subcommand", every live-proof invocation in
`25-01-EQUIVALENCE-EVIDENCE.md` fails, and Criterion 1 has no operator surface at all.

---

## SEAM-25-3 — `crates/wcore-cli/src/main.rs`, part B (the dispatch arm)

**Insertion point:** in the `match` over `TopCmd`, immediately after the existing
`TopCmd::Fetch(args) => match wcore_cli::fetch::run(args).await { … },` arm (around line 1352).

**Exact lines to add:**

```rust
            TopCmd::Backend(args) => match wcore_cli::backend::run(args).await {
                Ok(()) => Ok(ExitCode::SUCCESS),
                Err(e) => {
                    eprintln!("wayland-core backend: {e:#}");
                    Ok(ExitCode::FAILURE)
                }
            },
```

**What breaks if omitted:** the `match` is non-exhaustive and `wcore-cli` fails to compile. Even
if it did compile, the subcommand would parse and then do nothing.

## Correction to a fenced-file assumption in the 25-01 plan

The plan directed adding **`wcore-sandbox`** to `FORBIDDEN_CORE_IMPORTS` in
`crates/wcore-plugin-api/build.rs` (not a fenced file, so no seam request is needed — recorded
here only because the integrator may expect the change and not find it).

**It was deliberately NOT made.** `wcore-plugin-api/Cargo.toml` already carries
`wcore-sandbox.workspace = true` as an explicitly annotated M5.1 security-allowlisted dependency,
because `PluginContext` hands plugins an `Arc<SandboxRegistry>` handle. Adding it to the forbidden
list fails the build of the existing tree — measured on hetzner-dsm, `build.rs` exit 101. Only
`wcore-exec-backend` was added. The reasoning is recorded in `build.rs` next to the list and pinned
by a test.
