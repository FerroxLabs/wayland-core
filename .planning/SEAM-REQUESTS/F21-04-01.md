# Seam requests — F21-04-01 (no per-child observable on the host protocol)

**Finding:** `21-04-ATTRIBUTION-RESULTS.md:217`, `21-04-PHASE-VERDICT.md:118`, HIGH.
**Repair branch:** `fix/F21-04-01`.
**Fenced files this repair may NOT touch:** `crates/wcore-protocol/src/contract/generate.rs`,
`crates/wcore-protocol/contracts/desktop/v1/manifest.json`, and any `wcore-contract generate` run.

## 0. What was repaired WITHOUT a seam, and why the seam is smaller than the finding

The finding named four missing per-child observables (reservation, refund, escalation,
cancellation) plus sibling identity on `approval_required`. Root-causing it split the
finding in two.

The **producer-side half is repaired on this branch with zero contract change.**
`ProtocolEvent::SubAgentEvent` already carries `parent_call_id` + `agent_name` and an
opaque `inner`, and `spawn_tool.rs::spawn_with_relay` already wraps every `SubAgentRelay`
in it. The defect was that `ChannelSink` — the `OutputSink` installed into every spawned
child engine (`spawner.rs::execute_resolved_launch:2034`) — implemented only 10 of
`OutputSink`'s ~30 methods, so every other method kept the trait's **empty default body**
and the child's structured lifecycle events were discarded at the child boundary before
they could reach the relay. Overriding `emit_budget_exceeded` and
`emit_midflight_monitor_decision` on that sink puts the child's escalation and cancellation
facts on the shipped wire, attributed.

Verified live at `minor 8` with the three pinned digests unchanged
(`fixture sha256:0704cd43…`, `schema sha256:e5d1744a…`, `source_inputs sha256:9d5928b4…`);
the checked-in `sub_agent_event` schema branches carry `inner.additionalProperties: true`
with no `required` set, so an additive `inner` type is contract-conformant as generated.
A regression test pins that property so a future contract revision that closes `inner`
fails loudly instead of silently invalidating this repair
(`crates/wcore-agent/tests/child_lifecycle_observable_test.rs`,
`pinned_sub_agent_event_contract_admits_a_lifecycle_inner_without_regeneration`).

**Three items genuinely cannot be done producer-side.** They are below. Each states the
exact shape, the exact insertion point, and what breaks without it.

## 1. Coordination cost — read this before scheduling any item below

`crates/wcore-protocol/src/contract/observation.rs:329` makes a `minor` difference a
**hard error at `ready` negotiation**: the reference host decoder returns
`HostObservationError::ContractMinorMismatch` and the session is refused outright — it
does not degrade, it does not drop the unknown line. Adding any event or command to
`SOURCE_INPUTS`/`spec.rs` also moves `schema_digest`, `fixture_digest` and
`source_inputs_digest`, each of which is its own hard error on the same path
(`:335-345`).

Therefore **every item below is a coordinated Core+Desktop release, not a free additive
change.** The correct sequencing is: land the producer change and the regenerated corpus
in one Core cut, publish the digest bump the way
`.planning/intel/D1-CORE-PRODUCER-CONTRACT.md` §3.0 did
for revision 1→2, and ship the Desktop re-pin in the same release train. Batching all
three items into ONE bump costs one coordinated release instead of three.

## SR-F21-04-01-1 — `budget_reservation` / `budget_refund` events

**Files:** `crates/wcore-protocol/src/events.rs` (new variants),
`crates/wcore-protocol/src/contract/spec.rs` `SOURCE_INPUTS` + wire-spec table,
regenerated `contracts/desktop/v1/` corpus.

**Why it cannot be done producer-side:** there is no `ProtocolEvent` for a reservation or
a refund **on any actor**, parent or child — `grep -i "reservation\|refund"` over
`events.rs` and `commands.rs` returns nothing. `BudgetTracker::reserve_turn`,
`release` and `settle_turn` (`crates/wcore-budget/src/tracker.rs:859+`) are wholly
internal. Relaying an event that does not exist is not a producer-side option; the type
must exist first. Once it does, the per-child leg is free — it rides the same
`SubAgentEvent` envelope this repair already proved.

**Exact shape** (mirrors `BudgetExceeded`'s always-on additive class — no capability
flag, hosts that do not know the `type` drop the line per the W0 decoder contract):

```rust
/// One provider-budget reservation admitted for a turn. `session_id` is the
/// budget session the reservation was admitted against, NOT the transport
/// session, so a child that inherits its parent's budget session is visibly
/// spending the parent's envelope.
BudgetReservation {
    reservation_id: String,
    session_id: String,
    input_tokens: u64,
    output_tokens: u64,
    /// Omitted when the provider/model is unpriced.
    #[serde(skip_serializing_if = "Option::is_none")]
    cost_usd: Option<f64>,
},
/// A reservation released without being fully consumed. `settled_*` are the
/// amounts actually committed; the refund is the difference from the matching
/// `budget_reservation`.
BudgetRefund {
    reservation_id: String,
    session_id: String,
    settled_input_tokens: u64,
    settled_output_tokens: u64,
    #[serde(skip_serializing_if = "Option::is_none")]
    settled_cost_usd: Option<f64>,
},
```

**Exact insertion point:**
1. `events.rs` — immediately after the `BudgetExceeded` variant (currently `:1009-1013`),
   so the three budget variants stay adjacent.
2. `spec.rs` — two rows in the wire-spec table beside the existing `"budget_exceeded"`
   entry (`:610-611`), `criticality` **noncritical**, `correlation` keyed on
   `reservation_id`, `capability` `None` (always-on, same class as `budget_exceeded`).
3. Producer wiring (NOT fenced, can be done in the same PR): emit from
   `AgentEngine`'s reservation and settlement sites — `self.output` there is already the
   `ChannelSink` for a child, so `channel_sink.rs` gains two more overrides and the
   per-child attribution follows with no further work.

**What breaks without it:** two of Success Criterion 2's six named events — reservation
and refund — have no host-protocol expression at all, on ANY actor. A Desktop cost or
budget UI cannot show money in flight, only money already spent, and cannot attribute
either to a sibling. This is also the axis F21-04-02 is stuck on: with no wire event, a
refund across a restart cannot be observed from the host even once the durability defect
is fixed, so SR-1 is a prerequisite for closing F21-04-02 *on the host surface*.

## SR-F21-04-01-2 — a per-child stop command

**Files:** `crates/wcore-protocol/src/commands.rs` (new variant),
`crates/wcore-protocol/src/contract/spec.rs`, regenerated corpus.

**Why it cannot be done producer-side:** this is the **host → Core** direction.
`ProtocolCommand::Stop` (`commands.rs:142`) is a bare unit variant with no target, and it
cancels the whole turn. No producer-side change can give a host an addressing handle it
has no way to send. The Core-side plumbing already exists — `execute_resolved_launch`
gives each child its own `child_cancel` token derived from the parent
(`spawner.rs:2048`), so the child token is already the right granularity; only the wire
verb is missing.

**Exact shape:**

```rust
/// Cancel ONE delegated child without terminating the parent's turn.
/// `parent_call_id` is the same handle `sub_agent_event` already carries, so
/// a host addresses exactly what it rendered.
StopChild {
    parent_call_id: String,
},
```

**Exact insertion point:** `commands.rs`, immediately after `Stop` (`:142`), so the two
cancellation verbs read together. `spec.rs`: one command row beside `"stop"`, with
`additionalProperties: false` (matching the other closed command branches in
`generate.rs:959-975`, the closed-command list ending at `branch["additionalProperties"] =
json!(false)`).

**What breaks without it:** cancellation is observable per child after this repair (the
mid-flight monitor's `Stop` decision now relays with the child's identity) but not
*actionable* per child. A host watching one runaway sibling in a fan-out can only kill
the entire turn, taking every healthy sibling with it. Phase 22 supervises fleets of
children, so the blast radius of "stop" grows with fan-out until this lands.

**Why a NEW variant rather than extending `Stop` — measured, 2026-07-27.** The obvious
cheaper-looking alternative is to widen the existing verb into
`Stop { #[serde(default)] child: Option<String> }`. `ProtocolCommand` is internally tagged
and derives only `Deserialize`, so that *is* decode-compatible — `{"type":"stop"}` still
parses. **Take the new variant anyway**, because the same probe shows the failure mode that
choice would buy:

```
legacy-stop-on-new-shape  = OK -> Stop { child: None }
scoped-stop-on-new-shape  = OK -> Stop { child: Some("c-1") }
old-decoder-on-scoped     = ACCEPTS, ignores unknown field -> Stop
```

An un-upgraded Core **accepts** `{"type":"stop","child":"c-1"}` and silently discards the
target, so a scoped stop from an upgraded host kills the entire turn — the exact blast
radius this item exists to remove, reintroduced silently and with no error. `StopChild` is
an unknown *variant* to that same decoder, so it fails loudly instead. Prefer the loud
failure: this is a cancellation verb, and a silent over-broad kill is the worst outcome in
the set.

Reproduce: `.planning/intel/evidence/F21-04-01-serde-probe/` (`cargo run -q`, standalone,
asserts the first three cases and reports the fourth).

## SR-F21-04-01-3 — child identity on approval, and a producer for it

**Files:** `crates/wcore-protocol/src/events.rs` (`ApprovalRequired`),
`crates/wcore-protocol/src/contract/spec.rs`, regenerated corpus — **plus a product
decision that is not a contract change.**

**State of the world, measured at this HEAD — the finding is half right here.**
`ApprovalRequired` indeed names no sibling. But wrapping it in `SubAgentEvent` (the fix
used for budget and cancellation) would today be **dead code**, because a spawned child
has no approval producer at all:

* `spawner.rs::child_tool_registry` → `build_tool_registry` (`:2396`) admits only
  `Read/Write/Edit/Bash/Grep/Glob`. No `ScriptTool`, which is the only holder of
  `OutputSinkScriptAdapter` (`bootstrap.rs:2440`).
* That adapter is constructed over `self.output` — the **parent's** sink — not the
  child's, so even a future child ScriptTool would emit against the parent.
* The child engine is never given an approval manager or protocol writer
  (`spawner.rs:2130` states this as a deliberate invariant).

No override was added for `emit_approval_required` / `emit_suspend` /
`emit_approval_resume` on this branch, because AGENTS.md §2 forbids speculative code and
an unreachable relay is exactly that.

**Two things are therefore requested, in order:**

**(a) A product decision (Sean, not fenced):** should a delegated child ever be able to
raise an approval a human answers? "No — children run inside the parent's already-approved
envelope" is a legitimate and defensible answer, and if it is taken, the approval leg of
F21-04-01 should be **closed as not-applicable** rather than left open, and
`21-04-ATTRIBUTION-RESULTS.md:217` amended to say so. Nothing below is needed in that case.

**(b) Only if (a) is "yes" — contract fields:**

```rust
ApprovalRequired {
    call_id: String,
    resume_token: String,
    correlation_id: String,
    reason: String,
    context: String,
    plan: Option<CruciblePlan>,
    /// Present only when a DELEGATED child raised this approval; absent for a
    /// parent-raised one. Same handle `sub_agent_event` carries, so a host
    /// renders the modal against the sibling it already has on screen.
    #[serde(default, skip_serializing_if = "Option::is_none")]
    parent_call_id: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    agent_name: Option<String>,
},
```

**Exact insertion point:** two optional fields appended to the existing `ApprovalRequired`
variant (`events.rs:969-983`); no new event type. `spec.rs`'s `approval_required` row is
unchanged in shape but its fixture must be regenerated. Because both fields are
`Option` + `skip_serializing_if`, the emitted bytes for a parent-raised approval are
byte-identical to today — but the digests still move, so §1's coordination cost applies
regardless.

**What breaks without (b), given (a) = yes:** a host cannot tell which sibling is blocked,
so it cannot route the modal, cannot show which work is stalled, and cannot resolve two
concurrent sibling approvals independently. Answering the wrong one is silent and
unrecoverable.

## 4. Not requested, deliberately

* **TUI rendering of the two newly relayed inner types.** `protocol_bridge.rs`'s
  `apply_sub_agent_event` (`:1750`) has a `_ =>` catch-all, so `budget_exceeded` and
  `mid_flight_monitor_decision` are ignored gracefully rather than mis-rendered. Adding
  feed lines is a UI improvement, not part of this finding, and belongs to Phase 22's
  Criterion 1 (CLI/TUI/host-protocol observing IDENTICAL state) where it can be designed
  against all three surfaces at once.
* **Relaying the other `OutputSink` methods a child reaches** (`emit_trace`,
  `emit_session_cost`, `emit_capability_activation`, `emit_compaction`,
  `emit_provider_retry` / `emit_provider_failure`, `emit_tool_panicked`). All are dropped
  by `ChannelSink` for the same root cause, none is on Success Criterion 2's named set,
  and `emit_trace` / `emit_session_cost` ride capability flags (`structured_traces`,
  `cost_attribution`) that the `sub_agent_traces` envelope would bypass — a decision that
  needs its own design, not a drive-by. The class is documented at the top of
  `channel_sink.rs` so the next author sees it.
