causes: a `cache_read` that was flat rather than falling never reached
`attribute_cause` at all, and the messages array was never hashed, so a
changed prefix could not be named even when it was the cause.

All four graded defects are closed and the snapshot moved to after the tier
swap, so it describes the request that actually went on the wire. A healthy
control is included deliberately — a detector that can only say "broken" is
as useless as one that can only say "fine".

were both anchored on bare `engine.rs` / `cache_diagnostics.rs` line numbers

because a `file:<path>:<line>` token only asks whether the file is that long.
Both are re-anchored on tests; c4's is a new source lint, because that
criterion is about ordering inside one function and there was nothing else to
point at. No code moved for either.

Re-graded at e7144c30a on 2026-08-29. c1-c4 hold. c5 did not: the absolute
floor c1 added fired on turns where the whole prefix HAD been read back and
only the new input had grown, reporting `PartialMiss { TtlExpiry }` and
writing a durable `expired` invalidation into the ledger for an event that
never happened — Defect 4 re-entering through the fix for Defect 1. Both
controls in the file sat far from that boundary. The floor now measures
`cache_read` against the previous turn's total input instead of only against
this turn's, which still fires on the #559 leader trace (0.031) and no longer
fires on a reused prefix (0.988). c6 is the ticket's fifth defect, which had
no criterion here at all.
