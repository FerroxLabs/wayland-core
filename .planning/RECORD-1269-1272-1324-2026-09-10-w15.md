### 1.2 c2 — `schema_digest` cannot move, and the construction is readable in-tree

The criterion's literal question is "confirming whether `schema_digest` moves".
No regenerate was run. But the key it names is settled by construction, and so
is one of the other two.

**`schema_digest` — cannot move.** `schemas_digest`
(`crates/wcore-protocol/src/contract/generate.rs:1412-1417`) hashes ONLY
artifacts whose path starts with `schema/`. The three checked-in schema files
(`schema/core-event.schema.json`, `host-command.schema.json`,
`producer-complete.schema.json`) contain **zero** non-integer numeric literals
— measured, not assumed. The sibling `wire_shape_digests` doc comment
(`generate.rs:1422-1424`) states the rule directly: a schema branch is
"Value-independent (a branch records types, enums and nesting, never fixture
values)". A float-rendering change cannot reach bytes that contain no floats.

**`source_inputs_digest` — cannot move.** `source_inputs` in
`crates/wcore-protocol/contracts/desktop/v1/manifest.json` has 43 entries;
the root `Cargo.toml` is not one of them (measured: zero entries containing
`Cargo.toml`). Correcting the recon: 25 of the 43 are OUTSIDE
`crates/wcore-protocol/src/`, so the "all under wcore-protocol/src" reasoning
was wrong even though the conclusion holds.

**`fixture_digest` — narrowed, not settled.** `fixtures_digest`
(`generate.rs:1376-1408`) hashes each fixture's bytes VERBATIM, with exactly
one exception: six negotiation fixtures are parsed with
`serde_json::from_slice`, have their embedded `fixture_digest` zeroed, and are
re-emitted through `canonical_json` (`generate.rs:1386-1401`). That parse is
the only place inside the digest path where `serde_json`'s parse precision
could bite. All six carry **zero** non-integer numeric literals — measured:

```
events/ready.json                                  floats=[]
compat/events/ready.journaled-without-replay.json  floats=[]
compat/events/ready.disabled-by-host.legacy.json   floats=[]
adversarial/events/version-mismatch.jsonl          floats=[]
adversarial/events/schema-mismatch.jsonl           floats=[]
adversarial/events/fixture-mismatch.jsonl          floats=[]
```

The 24 fixture files that DO carry a non-integer numeral are all outside that
list, so their bytes enter the digest unparsed. The 7 distinct values across
all 200 fixture files are `0.0`, `0.0125`, `0.875`, `1.25`, `2.5`, `5.0`,
`87.5` — at most 3 significant digits each.

The residual, stated as a limit rather than resolved: the `artifacts` map
`fixtures_digest` consumes is what the GENERATOR produces, not what is on disk,
so a regenerate is still the only instrument that grades the generator's own
serialisation path end to end. The prediction this record makes, and which a
regen would falsify if wrong: **no key moves.** `serde_json`'s `float_roundtrip`
is documented as affecting decimal PARSING precision, and only for decimals a
fast path cannot round-trip (17-plus significant digits); serialisation goes
through `ryu` either way. That is library semantics, external to this tree, and
is labelled as such.

**c2 stays NOT MET**, and two of its three reasons are now permanent rather
than pending: (a) no regenerate was run, and (b) `float_roundtrip` is already
in the shipped tree at `Cargo.toml:236` (landed by `93ede3424`), so the
"before it is merged or discarded" clause can no longer be satisfied by
anybody. What remains achievable is a post-hoc confirming regen on a Linux
host, and the record above says what it should find.
