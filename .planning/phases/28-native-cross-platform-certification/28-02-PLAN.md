<objective>
Settle by measurement whether the Windows sandbox is observable in the certification environment, and then run the E5 hostile matrix natively on macOS, Linux and Windows against the resolved candidate — with every sandbox green carrying positive evidence that a sandbox was actually there.

Purpose: Criterion 1 requires the hostile platform matrix to pass with no skipped critical case. The single largest threat to that is not a missing probe, it is an inherited belief. The program has been discounting Windows sandbox reds as artifacts of an unobservable channel; that belief is now contested, with a concurrent investigation attributing the false negative to a stale-lease wedge rather than the logon session. If the belief is wrong it has been concealing real failures, and a certification that inherits it bakes the concealment into its own gate. So the first thing this plan does is stop inheriting and start measuring.
Output: a control verdict that distinguishes a broken observation channel from a broken product and from a wedged lease; nine dimensions of black-box probes driving the shipped binary on all three OS families; and a per-cell result set in which every red is attributed, every skip carries a legal class with its evidence, and every sandbox green carries an activeness observation.
</objective>

**CONTROL BEFORE VERDICT — THIS IS THE ORDERING CONSTRAINT AND IT IS NOT NEGOTIABLE.** Task 1 completes and its verdict is recorded BEFORE any sandbox-dimension cell is graded in task 3. No Windows sandbox result may be recorded as an artifact, discounted, or skipped on the basis of any belief this plan did not measure. If task 1 cannot produce a control verdict, sandbox cells are RED, not skipped — an ungraded critical cell is a skipped critical case and Criterion 1 forbids it.

**ASSUME NEITHER ANSWER ABOUT SSH OBSERVABILITY.** The old belief (session-0 logon makes the probe report unavailable regardless of correctness) and the new report (a stale-lease wedge causes it, and clearing leases restores observability over SSH) are BOTH hypotheses here. The control is designed to discriminate them, including the case where both are partly true. Read `.planning/intel/APPCONTAINER-SSH-LEASE-WEDGE.md` if it exists; if it does not exist yet, proceed with the control unchanged — this plan does not wait on it and does not depend on it.

**IF THE CONTROL SHOWS THE CHANNEL IS SOUND, RE-EXAMINE WHAT THE OLD BELIEF DISCOUNTED.** That is part of this plan's job, not a follow-up. Enumerate the Windows sandbox reds previously written off as artifacts, re-run those that are re-runnable in the certification environment, and record each as confirmed-real, confirmed-artifact, or not-re-runnable-with-reason. A belief that discounted real failures is itself a finding, and it is scored under the 28-01 rubric like any other.

**PROVE IT ON THE REAL PRODUCT.** Every cell drives the shipped `wayland-core` binary. A live run is specified by three things and is not accepted without all three: the EXACT invocation — binary, flags and input; an OBSERVABLE OUTCOME that distinguishes pass from fail; and the NAMED PLATFORM. "Verify it works" is not a verification step and no gate in this plan accepts it. In-process assertions are permitted as an ADDITIONAL leg and are never sufficient alone.

**ENVIRONMENT — the traps here have each cost hours.**
- **Windows OpenSSH kills session children on disconnect.** Never run a long build or matrix leg directly over ssh. Register a scheduled task, run it, log to a file, and poll that file for an exit marker. Measured on the real box: an ssh-spawned child wrote 1 of 600 heartbeats and was gone; the same binary under a scheduled task ran to completion. The ssh call returning tells you nothing.
- **SSH into PowerShell breaks on naive quote nesting.** Write the whole leg as a `.ps1`, encode it base64-as-UTF-16LE, and invoke with `-EncodedCommand`. `#< CLIXML` on stderr is noise, not failure.
- **The two Windows runners are ONE physical box.** Serialize. Every recorded row names the single quiet run it came from. Under parallel load a sandbox admission path rejects fail-closed, which is safe but looks exactly like a product defect — a red produced under concurrent load is not a recordable red.
- **`cmd` `set VAR=x && ...` appends a trailing space** and the parse silently falls back to a default. Use the quoted form and PROVE the variable took effect before trusting anything downstream.
- **PowerShell 5.1 parses a high hex constant as a negative Int32**, so handle-opening probes "succeed" holding nothing. Prefer probes compiled into the crate or driven through the shipped binary over PowerShell-authored ones.
- **Windows CI runs clippy with `-D warnings` BEFORE tests**, so a lint failure means the tests never execute and the run looks clean. Lint first, deliberately.
- **hetzner-dsm:** worktree `/root/wayland-p28`, `cargo` at `/root/.cargo/bin/cargo` (a bare `cargo` exiting 127 is PATH, not a build failure), targeted `-p` builds only, check `df -h /root` first, and treat a connection timeout as load to back off from.
- **macOS:** the certification Mac may run the shipped binary and may NOT run cargo beyond `cargo fmt --all -- --check`. The arm64 binary comes from the CI per-target artifact. A cell that genuinely cannot be driven black-box is declared harness-bound with its consequence stated; it is not silently dropped.
- Mac `grep` and `ls` are rtk-proxied and SILENTLY DROP LINES — always `/usr/bin/grep`, `-F` for literals, `/usr/bin/git` for git.

**TERMINATION CRITERION FOR THIS PLAN (hard).** This plan measures ONE control, authors ONE probe set, and executes the matrix ONCE per OS family. It terminates in exactly one of four states, and in all four it writes its SUMMARY and stops:
1. **Complete.** The control produced a verdict, the probe set covers all nine dimensions, the matrix ran on all three families, and every cell has a recorded outcome. Write the SUMMARY and stop.
2. **Complete with stated exceptions.** As above, but one or more cells are RED, or an OS family is partially covered because a probe is harness-bound where no harness can be built. State exactly which cells, on which family, and what evidence would close them. This is a PASSING state for the plan and an HONEST one for the phase.
3. **Terminated — the control is inconclusive.** The control cannot distinguish a broken channel from a broken product. STOP grading sandbox cells, record them RED with the control's raw output, and escalate. Do NOT fall back to the inherited belief, and do NOT use the observation-blocked skip class without a passing control.
4. **Escalated — the harness cannot be made to work.** Bounded at TWO repair iterations of the HARNESS, where an iteration is one edit-build-run cycle on real hardware. After the second, STOP, record every remaining failure with its output, and escalate.
Under no circumstances does this plan repair a production defect it finds, modify any production file under `crates/*/src` outside `wcore-eval-scenarios`, modify or delete an existing test, sign a receipt, run the soak, create a fifth Phase 28 plan, or add a fifth skip class.

**THE PHASE PLAN CAP.** Phase 28 is capped at FOUR plans. This is the second.

|----------|-------------|
