<objective>
Close the single-access-bit Windows defect that fails 10 of the 13 remaining `wcore-swarm` tests: the repository-root `DirectoryAuthority` is opened with the `DELETE` access right, which makes `SetCurrentDirectory` — and therefore git's in-process `chdir()` inside `setup_work_tree()` — fail with a sharing violation for the whole lifetime of a `WorktreeManager`. Add an OBSERVATIONAL directory-open path to `wcore-sandbox`, use it for the repo-root authority only, prove the invariant with a regression test, re-measure the predicted second layer, and claim the pass solely from SEANDESKTOP.

Purpose: `repo_authority` is a pure identity witness — its only consumer in the crate is `validate_repo_authority`, which calls `validate_path`. It never mutates, deletes or renames. It nevertheless holds `GENERIC_READ | GENERIC_WRITE | DELETE` (`directory_authority_windows.rs:57`), and because `SetCurrentDirectory` opens its target without sharing DELETE (so the current directory cannot be deleted out from under a process), any outstanding DELETE-bearing handle makes every NEED_WORK_TREE git subcommand in `repo_root` die with `fatal: this operation must be run in a work tree`. `assert_clean` therefore fails unconditionally on Windows once a manager exists, and it gates dispatch, isolated checkout and integration checkout alike. Dropping DELETE from THIS authority removes a capability it never exercises: the handle is still retained, identity is still FileId/volume-based, and `validate_path` still fails closed — this is least privilege, not gate-weakening.
Output: A documented, drift-resistant observational authority in `wcore-sandbox`; the repo-root authority converted at both constructors; an invariant regression test; a measured decision on the predicted `git -C <checkout>` second layer; and SEANDESKTOP-green counts.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository root ← retained authority | The repo-root authority is the swarm's proof that `repo_root` still names the exact directory object held at construction; weakening that proof would let a same-path replacement redirect a clone source |
| child git process ← host directory handles | A handle the host holds can silently deny the child an OS operation (here: chdir), turning a host-side capability choice into a child-side functional failure |
| retained checkout ← cleanup capability | The checkout authority must retain delete access to remove the workspace; scoping when it is held must not create a window where the checkout is unowned |
| host repair claim ← real hardware | The Mac cannot compile this workspace; only SEANDESKTOP can prove or disprove the repair |
