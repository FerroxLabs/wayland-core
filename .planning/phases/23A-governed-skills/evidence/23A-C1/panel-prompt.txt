Rust CLI agent product. An autonomous "skill drafter" writes files into the user's GLOBAL
config skills directory (<config_dir>/wayland-core/skills/auto-<sig>/{SKILL.md,manifest.json})
with NO user action, triggered after N successful turns. The files are quarantined from
execution (both model-invocation and slash paths refuse them), and they ARE visible via
`/skill list` as "(hidden)". But there is no revoke and no rollback: nothing in the product
can undo the mutation of a directory the user owns. A separate memory-DB "Procedure" row
exists from a DIFFERENT code path, with no binding between the DB row and the on-disk file.

I must make this REVERSIBLE before making it capable. I cannot edit the CLI's main.rs
(fenced by another workstream), so new flags are out; crate-level binaries are an
established pattern in this repo and are available to me.

Proposed design:
1. New module `wcore-skills::govern`, state under <config_dir>/wayland-core/skills-governance/:
   - `journal.jsonl` append-only history (revoke/rollback events, timestamped)
   - `generations/<revocation_id>/` retaining the exact bytes removed
   - revoke(name) -> RevocationId: snapshot bytes -> append journal -> remove skill dir -> write tombstone
   - rollback(revocation_id): restore exact bytes -> append journal (history NOT erased)
   - is_revoked(name) -> bool, consulted by the drafter so a revoked draft is NOT re-created next session
2. `SkillDrafter::draft()` consults is_revoked() and suppresses re-creation.
3. A new crate binary exposes revoke/rollback/list; a seam request covers later main.rs wiring.
