<objective>
Deliver one persistent Core gateway runtime that an operator installs, starts, inspects, drains, restarts, upgrades and rolls back from the shipped binary — and prove that no delivery is lost or duplicated across any of those lifecycle events.

Purpose: Phase 24's first Success Criterion is the phase's spine. Every other criterion attaches to a runtime that is actually persistent: the automation plane needs a single long-lived scheduling owner, the channel framework needs a supervised process that survives a reconnect, and the typed client needs something to connect to that is still there after a restart. Today the pieces exist but are not one runtime — the cron daemon detaches itself in one place, the protocol server supervises profile children in another, and nothing owns drain, upgrade or delivery continuity.
Output: A `wcore-gateway` crate carrying the lifecycle state machine, native service management per OS family, a Windows-safe pid lock, drain, and a durable delivery ledger; the operator verb surface on `wayland-core`; every Phase-24 shared-seam edit landed once; and a recorded contract document holding the Windows detach measurement, the authorized Windows service mechanism, and the live delivery-count evidence from Linux and macOS.
</objective>
