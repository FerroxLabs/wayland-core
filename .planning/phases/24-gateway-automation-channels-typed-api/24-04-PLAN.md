    **THE JOURNEY TOOL — exact surface, and the ONLY receipt surface any gate in this plan invokes.** A new binary `wayland-journey`, declared as a fourth `[[bin]]` in the evaluation crate's own manifest at `bin/wayland-journey.rs`, clap-derive, every argument long-named and required exactly as `wayland-receipt` does it. Four subcommands, and each one names the ways it goes red:

    - `wayland-journey verify --receipt <PATH> --binary <PATH> --expect-platform <linux|macos|windows> --expect-commit <40-hex>`. Hashes `--binary` ITSELF with sha256 and requires the digest to equal the receipt's recorded binary digest — the verifier does the hashing so the check is independent of the driver that wrote the receipt. Exits non-zero when: the receipt is missing, empty or unparsable; the binary is missing; the computed digest differs from the recorded one; the recorded platform differs from `--expect-platform`; the recorded source commit differs from `--expect-commit`; the step list is not exactly the canonical ordered list; any step carries an empty command or empty captured output; `arrival_source` is not the independent-sink value; or submitted, arrived, unique, duplicates and losses do not reconcile. On success prints one line: `JOURNEY VERIFIED platform=<p> commit=<c> steps=<n> submitted=<n> arrived=<n> unique=<n> duplicates=0 losses=0`.
