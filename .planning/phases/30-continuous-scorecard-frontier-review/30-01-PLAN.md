<objective>
Independently review the capability ledger that already exists, take the surface inventory off the shipped binary's own command tree rather than off any planning document, and land the scorecard data structures the rest of Phase 30 is built on — with MET made structurally expensive and NOT MET made free.

Purpose: F30-01 and F30-02 both say the same thing in different words — Phase 30 REVIEWS an accumulated ledger, it does not author the first comparison. The two failure modes available here are reviewing a document by reading it (so an evidence ID that points at nothing reads exactly like one that points at something) and inventorying surfaces from planning prose (so a capability that exists only in `docs/` is counted as shipped). Both are closed by measurement: every evidence ID is resolved by running a command, and every surface is walked out of the real binary.
Output: a mechanical review of CTRL-01 with a severity on every defect and an UNRESOLVED marker on every evidence ID that does not resolve; a `scorecard` module and `wayland-scorecard` binary whose verdict enum refuses an invented grade at deserialization and whose verifier refuses MET on unproven evidence; and a per-surface truth table regenerated from the shipped binary and diffed three ways against `docs/` and the ledger's coverage families.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| capability ledger ← its own author | A ledger reviewed by whoever wrote it is a self-assessment; the review must be able to contradict it and must not be able to edit it |
