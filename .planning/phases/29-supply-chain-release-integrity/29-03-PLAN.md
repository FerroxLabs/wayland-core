<objective>
Teach the shipped updater the four things a Sigstore attestation cannot express — that an update must move forward, that a stale offer is not a current one, that a revoked version must not be installed, and that a signing key has a lifetime — and prove every one of them with a trust root generated at run time, without ever touching a real key or a real release.

Purpose: F29-02 asks the install and update path to verify signed manifests, source and artifact identity, rollback and freeze protection, revocation, key rotation, and trust roots. The path today does the identity half well and the lifecycle half not at all: there is no greater-than in the updater, no persisted state, no revocation vocabulary and no key with a lifetime. The failure mode to avoid is replacing the good half while adding the missing half, so every new check is ANDed with the existing provenance verification and the count of its call sites is a gate.
Output: an ordered, hostile-tested update decision extracted into a pure function; a bundled release trust root that refuses to construct from a placeholder exactly as the marketplace index already does; persisted freeze protection, revocation enforcement and a full key-rotation and compromise drill; a cross-implementation test pinning the manifest wire format; and an honest per-clause result table naming every point where Sean's real key or a real published release is the only missing input.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| updater ← release API response | Everything the updater learns about what to install comes from a remote response that an attacker on the path, or a hostile mirror, may control entirely |
| updater ← release manifest | The manifest is the only structured statement of sequence, age and revocation; its authenticity must be established before any field in it is believed |
| updater ← bundled trust root | The trust root is the one thing shipped inside the binary and therefore the one thing not fetched; if it is permissive, nothing downstream matters |
| updater ← persisted freeze state | The high-water mark is on the user's disk and is the memory that makes a freeze detectable; a reset of it is a downgrade of protection |
| running binary ← swapped binary | The atomic swap is the last moment anything can be checked; after it the attacker is the product |
| plugin installer ← third-party plugin | A separate trust root on a separate lifecycle, owned by a different phase, and not closed here |
