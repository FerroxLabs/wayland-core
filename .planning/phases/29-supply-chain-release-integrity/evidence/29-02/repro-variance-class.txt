F29-02 / TASK 3 -- VARIANCE CLASS: path_prefix
captured: 2026-07-27T23:50:34Z

CLASS: the ABSOLUTE BUILD-DIRECTORY PATH is embedded in the shipped
binary, so the artifact digest moves when the same source is built in a
different directory. Maps to release_integrity::VarianceClass::PathPrefix.

==========================================================================
HOW THE CLASS WAS IDENTIFIED (single variable, two observations)
==========================================================================
A: two clean target dirs at DIFFERENT paths  -> digests DIFFER
B: two clean builds at the SAME path         -> digests IDENTICAL

That pair is the identification. Everything else -- commit, lockfile,
toolchain, --locked, profile, host, user, environment -- was held fixed
across both observations, so the target-directory path is the only input
that changed when the outcome changed.

==========================================================================
THE MECHANISM, LOCATED
==========================================================================
The embedded paths are cranelift-codegen's build-script OUT_DIR, reaching
the binary through file!() in ISLE-generated sources. cranelift-codegen
arrives via wasmtime (the plugin/WASM runtime).

The differing build-id is a CONSEQUENCE, not an independent cause: it is a
hash of the linked content, and observation B shows it is stable when the
path is stable. Per the plan, the hunt stops at a class that explains the
difference; it does not enumerate every downstream effect.

==========================================================================
WHAT THIS MEANS FOR THE SHIPPED RELEASE
==========================================================================
The shipped release is reproducible IN PRACTICE but only ACCIDENTALLY.
GitHub-hosted runners always check out at the same absolute path
(/home/runner/work/wayland-core/wayland-core), so release.yml's builds
hold the varying input constant without ever intending to. A third party
rebuilding at any other path gets a different digest and cannot confirm
the artifact -- which is exactly the property reproducibility is for.

REMEDY, not applied here (release.yml is outside this plan's fence):
  RUSTFLAGS='--remap-path-prefix=$CARGO_TARGET_DIR=/build' (and the same
  for the source root), or the -Ztrim-paths / trim-paths profile option
  once stable. Either pins the class to a constant and should move this
  verdict to REPRODUCED. Filed for 29-04 / release coordination.

NOT MEASURED HERE, stated rather than implied: whether this same class is
the ONLY variance on macOS and Windows. That needs Phase 28's native
hardware and is explicitly out of this plan's scope. The aarch64-Linux
release leg additionally goes through 'cross' (see F29-CEN-06 / SR-29-7)
and was not measured at all.
