STATE THE LIMITATION FIRST, NOT LAST
------------------------------------
The end-to-end network path through `gh attestation verify` is NOT reachable
through the shipped entry point at this commit, and it is not reachable for a
reason this plan created: the signed-manifest gate now refuses a forward move
BEFORE the archive is downloaded, so the attestation check is never reached
while release manifests do not exist. That ordering is correct — you must not
download and verify an archive you have already decided not to install — but it
means this leg is proved at the unit level plus by measurement of the source,
not by a network round trip. Saying otherwise would be an overclaim.

------------

        Starting 1 test across 49 binaries (2240 tests skipped)
        PASS [   0.016s] (1/1) wcore-cli self_update::tests::verify_provenance_fails_closed_without_gh

That test injects a program name that does not exist
(`wayland-core-no-such-gh-binary-xyz`) and asserts the resulting error carries
the actionable guidance rather than a silent skip. Injection is the right
instrument here because `gh` IS present on this host:

    $ command -v gh
    /usr/bin/gh

so the NotFound branch cannot be reached by absence on this machine, and
removing a system `gh` shared by five concurrent lanes would be vandalism.

existing attestation check and nothing substitutes for it. Measured at this

The call sites did not shrink, the pinned repository constant survived, and no
runtime environment read was introduced. The archive-digest binding added by
this plan sits IMMEDIATELY BEFORE `verify_provenance` and returns early only on
mismatch; on the accept path the attestation call runs exactly as it did.
