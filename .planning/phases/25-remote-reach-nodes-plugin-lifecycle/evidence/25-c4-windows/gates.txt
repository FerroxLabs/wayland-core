=== RAW SOCKET PROBE — the RED is the PLATFORM, not the product ===
Same experiment as the test, with no wayland-core code in it at all: bind a
loopback listener on an ephemeral port, Stop() it, then connect to that port.

  probe 1 port=56492 NO-ANSWER-IN-2000ms elapsed=2042
  probe 2 port=56494 NO-ANSWER-IN-2000ms elapsed=2011
  probe 3 port=56496 NO-ANSWER-IN-2000ms elapsed=2013

Windows sends no RST for a just-released loopback ephemeral port — the SYN is
dropped, so the connect TIMES OUT. The test's premise, "closed listener must
refuse the connection", is a Unix assumption. wcore-egress classified what
actually happened (Timeout) correctly; the assertion demanding Connect is what
is wrong on this platform.

NOT FIXED, and deliberately not: weakening the assertion to accept either class
would be engineering a green. Reported RED with the output, per LANE-BRIEF §5.

=== registry::tests — a HARNESS mismatch, not a regression ===
`registry::tests` sets the process-global WAYLAND_EXEC_BACKEND_STATE_DIR, with
an in-source comment stating the tests "are single-threaded per process under
nextest, which runs each test in its own process". `cargo test` runs them in ONE
process on a thread pool, so siblings race. With --test-threads=1: 10 passed,
0 failed, 77 filtered out. Confirmed, not a defect in the code under test.
