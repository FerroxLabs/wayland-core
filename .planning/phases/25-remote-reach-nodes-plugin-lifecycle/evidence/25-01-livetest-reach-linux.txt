STATUS: 400
CT: Content-Type: text/xml;charset=UTF-8
BODY200: <?xml version="1.0" encoding="UTF-8"?><Response><Errors><Error><Code>MissingParameter</Code><Message>The request must contain the parameter AWSAccessKeyId</Message></Error></Errors><RequestID>4c8cee1...
VERDICT ec2-hibernate: REACHABLE, but the error surface is XML, not JSON. The workspace has no XML
parser in [workspace.dependencies], so every EC2 response would need hand-rolled parsing or a new
crate — and a new crate is a termination state. This is a REAL, MEASURED strike against
ec2-hibernate that the plan's own option text did not anticipate, and it is stronger than the
dependency argument the plan expected to be decisive.

OVERALL: no connection failure, no HTML body, no redirect onto an SDK-only surface for any of the
three. All three are drivable by a wcore-egress client from the authoritative host. The only
measured discriminator is response encoding: JSON for fly-machines and e2b-sandboxes, XML for
ec2-hibernate.
