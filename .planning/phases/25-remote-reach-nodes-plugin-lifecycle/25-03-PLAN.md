<objective>
Build the node/device contract and prove Success Criterion 2: nodes pair, advertise capability, revoke, recover from being offline, and handle mixed versions — all without losing authority attribution.

Purpose: plan 25-01 proved that one Core can reach four execution surfaces. This plan answers the question that immediately follows for an operator with more than one machine: which machines am I allowed to use, what can each of them do, how do I take one away, what happens when one vanishes and returns, and — the clause that actually matters — can I still tell exactly whose authority produced any given piece of work afterwards. F25-03 names those six properties, and the fifth and sixth of them are where implementations usually quietly fail.
Output: a node contract layered above the execution-backend contract, a `wayland-core node` operator surface, a hostile contract test suite, and a two-host live transcript in which attribution is re-verified after every disruption.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| far-end node → pairing record | A remote machine asserts an identity this Core will subsequently trust with work |
| operator → revocation | A human decision must durably remove execution authority from a machine |
| node → receipt attribution | A node's claim about which work it produced is consumed as evidence |
| mixed-version node → capability negotiation | A node states a contract version that determines which policies it can honour |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-03-01 | Spoofing | `node/pairing.rs` | critical | mitigate | Pairing refuses a far end whose identity cannot be proven; identity derives from the same Ed25519 material as the receipt attestation, so there is one identity notion in the crate |
| T-25-03-02 | Repudiation | `node/attribution.rs` | critical | mitigate | Node identity is attested INSIDE the receipt attestation and cannot be set by a caller; a tampered node identity fails verification exactly as a tampered backend identity does |
| T-25-03-03 | Elevation of privilege | revocation as forget-only | critical | mitigate | Revocation refuses subsequent work with a named verdict and terminates in-flight work; a revoked node cannot re-pair itself, and re-pairing is an operator action |
