<objective>
Make the browser, computer-use and web surfaces publish readiness they have actually measured, and prove that doing so costs none of the sandbox, egress, approval or cleanup guarantees those surfaces already hold.

Purpose: the ready handshake's browser and computer-use flags are derived from whether a plugin crate survived linking — the repository's own release smoke test says so in its module docs. That means a machine with no browser backend and no display can still be told both capabilities are available. The protocol already carries an append-only activation ladder with an explicit unavailable stage and a fixed reason vocabulary, and the browser and computer-use crates already carry real probes. The work is to connect probes that exist to a vocabulary that exists, and to refuse to let that connection weaken the policy boundaries around it.
Output: a measured readiness audit taken from the running binary on three platforms; one decision on what readiness is published and how a host distinguishes it from the existing linkage flags — adjudicated by a four-way cross-audit panel over an identical evidence bundle whose measurable claims were settled on real hardware first, committed to with its dissent preserved; live probes wired to the typed activation chain with an honest unavailable-plus-reason on every failure path; the desktop contract regenerated byte-exact; and live proof that origin policy, downloads confinement, approval gating and orphan reaping all survive.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host ← advertised capability | A host and a user both act on the handshake; a claim the machine cannot deliver is a false statement crossing into another process's decision-making |
| browser ← target origin | Every navigated origin is untrusted input, and the redirect re-check exists because the first admission decision is not the last one that matters |
| filesystem ← browser download | A download destination is attacker-influenceable, so the downloads root is the boundary that keeps a page from choosing where bytes land |
| host OS ← computer use | Computer use drives the real desktop; the approval gate and the display/session precondition are what keep it bounded |
| process table ← backend lifecycle | A backend process outliving its session is a resource leak and a residual attack surface on the user's machine |
| desktop contract ← protocol change | The byte-exact manifest is consumed by another repository; an unregenerated or hand-edited manifest silently desynchronizes two products |
