**NO GATE ENDS IN A PIPE — AND THIS PLAN IS THE ONE THAT CERTIFIES, SO A SELF-PASSING GATE HERE CERTIFIES A LIE.** A remote command piped into `tail` or `grep -v CLIXML` reports the FILTER's exit status, which is 0 no matter what the remote did — measured on this branch: `ssh hetzner-dsm 'exit 9'` returns 9, `ssh hetzner-dsm 'exit 9' | tail -3` returns 0. On Windows, chaining `cmd /c "A"; cmd /c "B"` with a semicolon runs both and reports only B's status. Every remote gate below captures the status first with `rc=$?` and asserts `test "$rc" -eq 0`; Windows chains use `&&` inside ONE `cmd /c` plus `exit $LASTEXITCODE` — measured to short-circuit and to return non-zero on an early failure. Filtering is for reading, after the status is safe. The sibling trap, already found in `scripts/wayland-e2e-windows-soak.ps1` in this repo, is reading an exit code out of a block that also emits output: `$exit = & { cargo ... | Tee-Object ...; $LASTEXITCODE }` returns an ARRAY of every output line plus the code, so `if ($exit -ne 0)` is always true and a 12/12 all-PASS run reported failure. In `f27-packaged-smoke.ps1`, read `$LASTEXITCODE` on the line AFTER the pipeline, never from inside a block that also writes output.

**Git hygiene.** Use `/usr/bin/git` on the Mac. Stage the exact paths in `files_modified`, never `-A`, never `.`. No `Co-Authored-By` trailers.
