<objective>
Make import and export selective, provenance-preserving, and safe against the executable content that dominates a real peer install — proven by a payload that demonstrably CANNOT run while quarantined and demonstrably CAN once promoted.

Purpose: Success Criterion 2 asks for two things that pull against each other. Selective import must move persona, memory, skills, settings, assets, profiles and credentials — and on Sean's real install that is 540 skill directories and 12 personas, the large majority of which are executable payloads Core already knows how to run. Quarantine must make those inert on arrival. Core already solved this exact problem once, under GHSA-8r7g, for project-defined hooks: inert by default, and the foreign thing cannot trust itself. This plan applies that settled contract to imported peer state instead of inventing a second, weaker one.
Output: A classification and containment path for imported executable content; a provenance record per imported item; selection by item identity with a conservation invariant; the export half of the portable corpus; and a live proof on Linux that a real peer skill payload does not execute while quarantined and does execute once promoted.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| imported skill body → skill executor | A peer `SKILL.md` is a shell payload the executor already knows how to run |
| imported MCP definition → child process launch | A peer MCP entry's command and args already flow into a stdio server config that is spawned |
| imported hook definition → child process launch | The surface GHSA-8r7g closed for project configs, reachable again by a different route |
