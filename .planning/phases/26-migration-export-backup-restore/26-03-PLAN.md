<objective>
Give Core backup, restore and rollback that survive a real, uncatchable interruption and restore the exact pre-operation state — proven by killing the real process mid-flight on Linux AND on real Windows and diffing the real tree.

Purpose: Success Criterion 3 is the only criterion in this phase that cannot be satisfied by any amount of correct-looking code, because what it asserts is a property of what happens when the code STOPS running. Core ships no backup, restore or rollback at all today, while both peers ship documented ones with specific published behaviors. This plan builds that surface against the peers' published bar and proves the interruption property the way it has to be proven: by interrupting.
Output: Archive creation with an embedded manifest and safe publication; verification before restore; a write-ahead operation journal whose recovery pass undoes an interrupted operation exactly; explicit secret-source remapping across the four credential backends; and interruption proofs on Linux and on real Windows, each of which independently establishes that the kill landed mid-flight before its consistency assertion counts.
</objective>

**A FIFTH TRAP — MEASURED ON THE REAL BOX, AND IT MADE EVERY WINDOWS GATE IN AN EARLIER DRAFT OF THIS PLAN INCAPABLE OF GOING RED.** The Windows sshd default shell is PowerShell, so `ssh SeanD@seandesktop "powershell -NoProfile -Command \"…\""` passes through TWO PowerShell layers. The OUTER one expands `$LASTEXITCODE` — which is empty at that point — before the inner one ever sees it, so the inner `exit $LASTEXITCODE` runs with no argument and exits 0. Measured directly: `ssh … "powershell -NoProfile -Command \"cmd /c 'exit 42'; exit \$LASTEXITCODE\""` returns **0**, and an inner `if (\$LASTEXITCODE -ne 0)` arrives at the box as the syntax error `if ( -ne 0)`. Every `-Command` gate written that way reports success no matter what happens.

The two invocation forms need OPPOSITE escaping, and both were measured in both polarities:
- **`-Command` (two PowerShell layers)** — escape with a PowerShell backtick so the OUTER layer passes the variable through literally: written `` \`\$LASTEXITCODE `` in the gate. Measured: fails non-zero on `exit 42`, returns 0 on `exit 0`, and a per-step `if` fires and prints its marker.
- **`-File script.ps1; exit \$LASTEXITCODE` (one layer)** — do NOT backtick it. Here the outer PowerShell's own `$LASTEXITCODE` genuinely IS the child's exit code. Measured: returns 7 when the script exits 7, and 0 when it exits 0. Adding a backtick to this form makes the outer shell try to RUN `$LASTEXITCODE` as a command, which fails every time — a guaranteed red, which is just as useless.

One further measured consequence: the numeric exit code is FLATTENED to 1 by the `-Command` path, so the distinct per-step codes below do not survive as numbers. The `STEP-FAIL: <step>` marker each step prints DOES survive, and that marker — not the number — is what identifies which step failed.

**A SIXTH TRAP, ALSO PRESENT IN AN EARLIER DRAFT OF THIS PLAN.** Chaining several `cmd /c` calls in one PowerShell `-Command` and then reading `$LASTEXITCODE` reports only the status of the LAST one. A draft of the sync gate ran `git fetch`, then `git checkout --detach <SHA>`, then `git rev-parse HEAD`, and exited with the rev-parse's status — so a FAILED checkout still exited 0 while printing the OLD head, and the paired `grep -qF "$SHA"` could still match because a failed checkout's own error message quotes the SHA it could not find. That gate was green on a tree at the wrong commit. Every Windows step therefore checks its OWN status, and the SHA assertion compares the rev-parse OUTPUT ALONE — captured to its own file, isolated from any error text — against the expected value.

**THE MEASUREMENT TRAPS — ALL FOUR ARE LIVE IN THIS PLAN. Do not simplify them away.**
1. **Mac `grep` is rtk-proxied and SILENTLY DROPS LINES.** Every gate invokes `/usr/bin/grep` explicitly, `-F` for literals.
2. **A pipe replaces the exit status you care about.** The shape `ssh host 'cmd' | grep -v CLIXML` yields grep's status, not ssh's, so a failed remote build reports success — and this plan's Windows output is full of CLIXML noise, which is exactly the temptation. Filtering for READING is fine; filtering inside a GATE is forbidden. Use `ssh host 'powershell -NoProfile -File script.ps1; exit $LASTEXITCODE'`, redirect to a file, capture the return code on its own line, test it, and only then read the file.
3. **Reading an exit code from a block that also emits output.** A PowerShell block that tees output and then yields the last exit code returns an ARRAY of every output line plus the code, making a numeric comparison always truthy — this exact bug made an all-PASS Windows soak report failure. Read the status on the line AFTER the pipeline, never from inside a block that also emits.
4. **In `cmd`, an assignment chained with `&&` appends a TRAILING SPACE to the value** and Rust silently ignores it. Use the quoted assignment form or PowerShell's environment syntax, and PROVE the value took effect before trusting any run that depends on it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| archive file → restore | An archive is an untrusted input by the time it is restored: it may have been tampered with, moved between machines, or crafted |
| archive entry path → extraction root | Every path inside an archive is attacker-controlled and may attempt to escape the root it extracts into |
| operation journal → recovery pass | The journal is what recovery trusts to undo an operation; a torn or forged record misdirects the undo |
| source machine secret location → target machine | Where a secret lives is machine-specific for two of the four backends; carrying it verbatim produces a config pointing at nothing |
| live target home ← in-progress restore | The window in which a home is neither its old self nor its new self, which is exactly what an interruption exposes |
| concurrent operations → each other's journals | The hazard #181 already found for the crash sentinel: an unscoped marker makes unrelated processes act on each other's state |
