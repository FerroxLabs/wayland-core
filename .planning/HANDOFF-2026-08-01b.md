## 7. OPEN PRODUCT DEFECTS, ranked

1. **`#661` grep data loss on Windows** — `findstr` signals an unopenable target
   with exit ≤1 and the check is `!success && code != Some(1)`, so "could not
   open" reads as "no matches". The model then concludes a symbol is undefined
   and deletes code. Closed for POSIX exit-2 only; the regression test is
   `#[cfg(unix)]` (`grep.rs:283`). Also `GrepTool` alone among Read/Glob/Grep has
   NO `validate_user_path`. **NOT STARTED.**
2. **`RealFs::observe_file` unimplemented off Unix** (`vfs.rs:406-418`) — ships an
   exactly-once filesystem guarantee that cannot execute on Windows; fails at
   first crash recovery instead of at negotiation. Interim: refuse the capability
   up front. **NOT STARTED.**
3. **Log rotation impossible on Windows** — `set_len(0)` on an append-only handle
   is `ERROR_ACCESS_DENIED` (`log_rotate.rs:196-205`). **NOT STARTED.**
4. **Worktree cleanup reclaims nothing on Windows** — caller holds a live
   `DirectoryAuthority` clone and the Windows-only strong-count precondition
   refuses every removal (`worktree_cleanup.rs:261`). **NOT STARTED.**
5. **AppContainer probe 15s guard vs 10s ready deadline** — any run reaching the
   probe misses `ready` deterministically; 15s of dead time for a user mid-AV-scan.
   DECIDED design (not implemented): probe in background, emit `ready`
   immediately, block the FIRST sandboxed execution on the result. Do NOT raise
   the deadline — that hides it. Recorded in `WINDOWS-TRIAGE-2026-07-31.md` §9.1b.
6. VCR records response headers/URLs/bodies unsanitized; `dump_request_path`
   writes with no 0600; `doctor` prints MCP `command`/`url` verbatim (a `?token=`
   leaks).
