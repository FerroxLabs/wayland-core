WHAT CHANGED (c1's second branch, which the criterion explicitly permits)
Each matrix entry now carries `scope: in|out`, and an out entry must carry
`out_of_scope_reason` or the leg FAILS -- an undeclared skip is refused by the
same step that implements skipping. For an out leg the workflow writes
`<crate>-OUT-OF-SCOPE.txt` into the uploaded artifact, naming the reason, the
file the declaration lives in, and the carrier issue, and states in as many
words: "This leg tested ZERO mutants by declaration, not by failure." The
declaration is therefore in the ARTIFACT a reader downloads, not only in a job
log that expires.

SIDE EFFECT, worth stating because it is large: the four out legs no longer
start cargo-mutants at all, so the nightly stops burning 4 x 6 = 24 hours of
hosted macOS runner time per run producing nothing.

TO RE-ENABLE A LEG: shard it so a shard finishes inside the ceiling, or move it
to a runner without that ceiling, then flip `scope` to "in". Do NOT flip it back
on an estimate.
