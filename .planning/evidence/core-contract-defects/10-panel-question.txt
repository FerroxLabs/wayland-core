(`wcore-contract generate`). A test (`check_contract`) and a CI step both regenerate in

Measured defect: the generator's `inferred_schema()` combines >=2 distinct inferred array
item schemas with `oneOf`, but every object schema it infers is permissive
(`additionalProperties: true`, no `required`). Permissive schemas are never mutually
exclusive, so that `oneOf` is UNSATISFIABLE by construction. Result: the project's own
published schema REJECTS one of its own 52 corpus fixtures. Any external host validating
against the published contract rejects a valid frame. One-line fix: use `anyOf` there.

the LAST action before a release tag. My brief says: "If your change requires regeneration,
say so loudly and stop."

    -- they are RED today and stay red through the whole merge train -- and (ii) a separate
    GREEN test proving the one-line anyOf fix is sufficient, applied to an in-memory copy of
    the schema. Hand the generator fix over as a written seam request.

(B) DO land the one-line generator fix. Then the new gates read the generator's in-memory
    output and go GREEN. Exactly one existing test and one CI step go red -- both the byte-

    orchestrator regenerates once.
