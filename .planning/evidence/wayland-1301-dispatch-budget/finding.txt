THE FIXES (w15/win1301)
-----------------------
aa8f42912 perf(journal): read one durable child without cloning session state
    DurableChildStore::inspect cloned the whole ReducedSessionState to read one record, three times per
    dispatch. SessionJournal::durable_child takes the same lock and error and clones only that record.
    Share: 2.3-3.7 s of 55.7-76.2 s on WinHost; 2.34 s of 15.1 s on Linux.
07272c36b perf(journal): size published checkpoints from the directory listing
    checkpoint_directory_bytes opened every entry of the checkpoint store on every store. Entries whose
    whole name is exactly a valid_sha256_hex digest are published checkpoints -- created only by
    hard-linking a fully written and synced temporary, never rewritten in place by any production
    writer -- and are sized from the directory entry. Temporaries, leftovers and unknown names keep the
    per-file symlink_metadata open. Share: 6.3-10.1 s of 55.7-76.2 s on WinHost.
Neither touches a SOURCE_INPUTS file (durable_child.rs, session_journal.rs,
tests/durable_child_store_test.rs). Neither changes what the test proves: the same 1000-dispatch
budget constant, the same real dispatches, the same assertions, the same kill line.

VERDICT

LIMITS, stated so this is not over-read:
* Base on the same four VMs also cleared 1.5x (157.942 s); the baseline run on two OTHER VMs did not
  (182.977 s). VM draw moves this test by more than the fix moves any single round.
* Subtracting the median paired reduction (18.0 s) from the slowest base sample ever seen (182.977 s)
  gives ~165 s, which would miss 1.5x. That is an INFERENCE: the fix never ran on that VM.
* Isolation removes the shared-pool condition instead of measuring it; the shared-pool debug figure
  is 185.46-226.28 s (1.06x), and CI no longer runs this test that way on Windows.

NOT CHANGED, AND WHY
--------------------
The two LARGEST Windows costs are flat, not growing, and each is a design decision rather than a lane fix:
* path_identity (~2.2 ms per call, twice per journal append, ~9 path opens per call on Windows) is the
  rename-and-replace guard on the journal authority (`session_journal/lease.rs:550`). Not weakened.
* The child tool registry re-resolves node/npm/python3/git across PATH x PATHEXT for every child with no
  cache (`wcore-tools` toolchain discovery). Caching a policy input is a boundary decision.

NATIVE WINDOWS CHECK OF FIX 2 (07272c36b), WinHost, msvc toolchain
------------------------------------------------------------------
Why: no Windows run had yet ASSERTED fix 2's sizes. CI (Array) test steps were skipped by a runner-image
refusal, and the hosted A/B timed fix 2 without checking its answers. The open question was whether an
NTFS directory listing (DirEntry::metadata, built from FindFirstFileW/FindNextFileW with no per-file open)
reports the current size for a freshly created hard link.

TREE IDENTITY, BY BLOB ID, NOT BY NAME
  The WinHost fix tree was the 38f82b87f archive plus `git apply` of 38f82b87f..07272c36b. The first
  verification attempt REFUSED to run: all three fixed files had blob ids that did not match 07272c36b.
  Measured cause: WinHost's system Git sets core.autocrlf=true, so `git apply` outside a repository wrote
  CRLF. CR count equalled LF count in each of the three files (4649, 551, 1144); after CRLF->LF each blob
  id matched 07272c36b exactly; an untouched control file (orchestration/workflow/limits.rs) had 0 CR
  and matched its blob. The three files were then replaced with the exact bytes of `git show
  07272c36b:<path>`, re-verified on WinHost (blob ids 04760f37..., 3f632da1..., e237e6d4..., 0 CR, fresh
  mtimes so the build could not reuse stale objects), and only then did the check run.

  Consequence for the earlier WinHost measurements, measured rather than assumed: rustc 1.95.0 (msvc) on
  WinHost compiled a source file whose every line ending is CRLF and which has a newline inside both a
  plain and a raw string literal; both literals came out as `x\ny`, length 3, no CR. rustc normalises CRLF
  to LF on input, so a tree that differs only in line endings compiles to the same code, and the WinHost
  base-vs-fix A/B and the WinHost stage-instrument runs stand.
