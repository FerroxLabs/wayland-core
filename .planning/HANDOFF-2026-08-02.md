## 0. RULES THAT COST TIME TONIGHT — read before doing anything

**1. A commit that is not pushed does not exist.** The first repair wave lost
**9 of 10 lanes** — 4.2M tokens, 94 minutes — because agents committed inside
isolated worktrees that were destroyed on completion. Only the one lane that ran
`git push` survived. Every lane prompt must say *push after every commit and
report the pushed SHA*, and the orchestrator must verify that SHA resolves on the
remote before accepting the lane. The second wave did this and lost nothing.

**2. Check hetzner disk before believing a test failure.** `/root/lanes` grew to
**608 GB across 101 stale directories** and put the box at 98% (41 GB free). Two
"new test failures" in the merge gate were admission control correctly refusing:
`dispatch requires 43,486,543,872 bytes ... but only 42,433,069,056 are available`.
Clean up between waves:
`cd /root/lanes && rm -rf <dirs not currently in use>` — 607 GB reclaimed, 62% now.
**This also explains a long-standing mystery**: `multi_worker_output_exhaustion`
reading as "FLAKY 3/3" on Windows is not flaky, it is **disk-pressure-dependent**.
Re-check any historical "flaky" verdict against free space before trusting it.

**3. macOS-target clippy needs the cross-compile env.** A bare
`cargo clippy --target aarch64-apple-darwin` on hetzner fails in the *build
scripts* of `libsqlite3-sys`, `ring`, `aws-lc-sys` — that is a missing zig/SDK
environment, NOT a lint failure and NOT a code regression. Set the env or omit the
leg; do not report it as red.

**4. `cargo` is at `/root/.cargo/bin` on hetzner and is NOT on the default ssh
PATH.** `export PATH=$HOME/.cargo/bin:$PATH` first, or you get
`bash: cargo: command not found`.

**5. Still true and still absolute: NEVER run cargo on Sean's Mac.** `cargo fmt`
only. Linux → hetzner. Windows → SeanDesktop (`D:` only, never `C:\` root, never
touch `C:\actions-runner-*`). macOS → CI or `sean-mac-arm64`.

**6. Piping a script into `powershell` on Windows lets cargo eat stdin** and
silently truncate the rest of the script. Run from a file, or redirect stdin from
`NUL`. This silently produced a half-executed gate earlier.

**7. `rtk` summarises `git log`/`grep` output and hides things.** Use
`rtk proxy git ...` when the exact output matters. It hid a merge commit once and
a grep count tonight.
