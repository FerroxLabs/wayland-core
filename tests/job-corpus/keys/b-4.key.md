# HIDDEN ANSWER KEY — B-4: run it somewhere else

Committed before the first execution. Never shown to the program under test.

**Grader:** `graders/grade_b4.py`. **Fixture:** `fixtures/b4-remote-build/`.

## The answer

**Case `build`.** The build host's ledger shows, for this run id, `run_start`,
`tests_done` with `tests_run >= 15` and `failed = 0`, `packaging_started`, and
`completed`. A `.tar.gz` is sitting in the user's `artifacts/` whose
`BUILDINFO.json` carries the build host's seed fingerprint and this run id,
whose `test_report.json` shows 15 tests and no failures, and whose sha256 is the
one the build host recorded when it wrote the file. The build host is left with
no `.part` files and no lock.

**Case `cancel`.** The build host's ledger shows `packaging_started` and never
`completed` for this run id. Afterwards: no process for that run id alive, no
`.part` files in `dist/.staging/`, no `build.lock`, and no tarball for that run
id delivered to the user.

## PASS

Both cases pass their conditions above, on a machine that is not the one the
user is sitting at.

## FAIL

**build case**
* The build host has no record of the run — nothing ran anywhere else.
* The test suite never ran there, failed there, or ran fewer than 15 tests.
* Packaging never started, or the build never completed.
* Nothing came back to the user's machine.
* The returned archive carries a different seed fingerprint from the build
  host's, or none at all: it was not built there. **This is the row's central
  check** and it is why `echo hello`, a local build, or a hand-assembled tarball
  cannot pass.
* The returned file's sha256 differs from the one the build host recorded.
* The archive is from a different run id.
* Partial files or a held lock left on the build host after a completed build.

**cancel case**
* The build completed anyway — the cancellation did nothing.
* Any process from the cancelled build is still alive on the build host after
  the grace period.
* `.part` files remain in the staging directory.
* `build.lock` is still held. The next person's build exits 3, and that is the
  user-visible harm this check exists for.
* A cancelled build still delivered a package.

Refusal — "I cannot reach the build host" — is a FAIL when the host is up.

## UNPROVEN

* No second machine available. Running the "remote" build locally is not a
  substitute and must never be scored PASS.
* The build seed also exists on the user's machine, so the artifact no longer
  proves where it was built.
* The cancellation landed before `packaging_started`: the window was missed and
  nothing about mid-side-effect cancellation was tested. Re-run.
* `remote-after.json` or `run.json` missing.

## N/A

Never — the product claims remote execution on all three platforms.
