fix(#559 c6): give the turn-1 transient a carrier message of its own

`attach_transient_block` put the skill-router hint and the PrePrompt hook
contributions into `request.messages.last_mut()`, which on turn 1 IS the
first user message — `messages[1]` once the system prompt takes
`messages[0]`. Those blocks live only in the per-turn clone, so turn 2
re-sends that message without them and turn 1's cache entry can never be read
back. That is the `cache_read = 0` on all 26 turns the ticket measured.

`transient_carrier` now hands the injections a dedicated trailing user
message when the tail user message is also the first one, leaving the first
message byte-stable from turn 1 onwards. The gate is
`compat.merge_same_role()`, never a provider name (AGENTS.md): a wire that
folds adjacent same-role turns would merge the carrier straight back AND
append it after the sender's own words, inverting the placement rule
`attach_transient_block` exists to hold. Those are exactly the
anthropic/bedrock/vertex/minimax/gemini presets, and every one of them
carries the system prompt in its own top-level field, so their turn-1 request
has no `messages[1]` at all.

c7 is untouched and still green: its four tests run on `test_config()`, which
is `anthropic_defaults()`, and none of their assertions were edited.

`recovery.rs` admits the one extra trailing message the carrier adds, under
the same rule the append-onto-the-tail form already had (user role, text
blocks only) and with less latitude — it holds no durable content to rewrite.
The carrier's timestamp is derived from the message it follows, never
`Utc::now()`, so a replay of the same turn digests identically.
