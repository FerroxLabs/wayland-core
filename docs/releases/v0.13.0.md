# Wayland Core v0.13.0

**Stable — 2026-08-13.** GitHub **Latest**; npm dist-tag **`latest`**.

```bash
npm install -g @ferroxlabs/wayland-core
wayland-core --version        # 0.13.0
```

Already installed? `wayland-core self-update` verifies the release
attestation before it replaces the binary, and fails closed if it cannot.

---

## The short version

**255 commits** — 3 `feat`, 140 `fix`, 64 `test`, 20 `docs`. No breaking
changes. Where v0.12.26 was the largest release in the project's history,
this one is deliberately the opposite shape: a hardening release that goes
back over the surfaces that release opened and makes them true.

The organising idea, and it is the same one:

> **Nothing lies to the user, and nothing loses their data.**

v0.12.26 shipped the promise. v0.13.0 is what happened when we spent a cycle
trying to break it. Most of what follows was found by attacking our own
product rather than by a report from a user.

---

## The headline: MCP tool discovery actually works

If you ran with `compaction = "full"` and a large MCP server, the model could
not learn the name of a single one of that server's tools. Not a slow path or
a rare one — a hard ceiling, and the model behaved correctly by refusing to
guess names it could not see.

`ToolSearch` is the hydration path: its result is the only channel by which a
deferred MCP tool's name and schema reach the model. That result was being run
through the same line-folding text heuristic as build logs. Pretty-printed
JSON is full of lines that legitimately look alike — enum members, repeated
property blocks — so a whole catalogue collapsed into:

```
[
  {
[... 23 similar lines]
  }
]
```

Measured on a five-tool catalogue: 27 lines to 5, and zero of five names
surviving.

The damage was not only what the model could read. The engine parses that same
string to decide which deferred tools to force-admit into the outbound tool
list, so a folded catalogue hydrated **nothing** — even a correctly guessed
name never became callable, and every repeat search returned a byte-identical
body. That is the measured ten-identical-searches loop, arrived at from the
far end.

Three changes close it. Structured output no longer meets the line fold at
all; the fold's similarity measure now normalises by the longer line, so a
three-character `{` can no longer anchor a group and swallow its own object;
and `ToolSearch` results are given room to arrive whole rather than being cut
mid-object by a character-count truncation. A body that arrives corrupted now
says so in the log instead of silently hydrating nothing.

`compact_json` also learned to escape object keys. A tool whose schema
contained a property named `say "hi"` used to produce output that no longer
parsed — and MCP servers choose their own property names.

## Auto-approved tool calls are announced

Every tool call that skipped the approval gate — force mode, an allow-listed
tool, a command-scoped grant, or a tool you had just granted **Always** —
dispatched with nothing on the wire to say it existed. Hosts saw a tool start
running for a call they had never been told about.

There is now a `call_announced` frame carrying the same payload as
`tool_request`, emitted for exactly those calls. In the TUI this closes two
defects nobody had reported: an auto-approved call produced no tool card at
all, and never staged the file it touched — leaving it out of the right-rail
tree and out of `/rewind`.

**Host authors: you must consume `call_announced`, not merely tolerate it.**
Dropping it through a default arm is not enough — the `tool_running` behind it
still has no matching request, and a host that fails closed on that will exit
the turn. Register the call id from the frame.

## Your unsaved work is not collateral

The largest single family of fixes this cycle. The shell can no longer discard
unsaved work, an `Edit` cannot drop it as a side effect, and a redirect that
would truncate a file with unsaved changes is refused. The guard now covers
`rm` and `git` as well as the editor, keys on one path spelling so it cannot be
sidestepped by how a path is written, anchors every copy it takes under a ref
so nothing it saves can be garbage-collected out from under you, and knows
that a merge in progress is not the same thing as unsaved work.

## Locks that release when they should

A systematic sweep after the session journal's data-file lock was found
leaking through `fork()`, blocking an agent behind its own child in 47.6% of
reopens under load. The journal now unlocks on drop rather than relying on
`close(2)`; the same correction landed on the cron schedule lease, the gateway
pid lock, the eval candidate identity lock and snapshot publication.

## Saying only what is true

`sandbox status` no longer claims filesystem containment on Windows, where the
Job Object does not provide it — measured, not assumed. A tool description no
longer names the flag that bypasses it. Startup warnings are said once instead
of on every turn. And the engine now discloses requests that never returned a
response, rather than letting them vanish.

## Runs that need a human

A run that requires human contact it cannot reach now freezes its state
changes and exits, instead of proceeding as though nobody needed to be asked.

## Also in this release

- **DM pairing codes** — single-use codes wired into the runtime with an
  operator verb, so pairing a direct-message channel is a deliberate act.
- **MCP `tools/list_changed`** is honoured mid-session; a server that changes
  its surface no longer needs a restart to be seen.
- **Recovery** — a crash-interrupted session is recoverable, `ready` is
  guaranteed to be the first json-stream frame, and the resume scan is bounded.
- **Providers** — a rejected API key is no longer retried, an empty message
  body never reaches the wire, a permanently unreachable endpoint fails fast,
  and Windows connect failures are classified by WSA code rather than by
  matching error text.
- **Memory** — project memory stays out of your repository, and the project
  root is resolved before it becomes a key.

## Host contract

`minor` **13 → 14**, `major` holds at **1**. Additive only: `call_announced`
is a new event, no existing event changed shape, and the inventory is 23
commands / 60 events / 17 capabilities.

Hosts that pin the contract descriptor must re-pin `fixture_digest` and
`source_inputs_digest`. `schema_digest` is unchanged. Hosts that ignore unknown
event types are unaffected — but see the note above: ignoring `call_announced`
is not the same as being unaffected by it.
