# Integrating Wayland Core 0.12.26 into Wayland Desktop

**Audience:** the Wayland Desktop lane (`FerroxLabs/wayland`, `app/`).
**Core version:** `v0.12.26` (stable, npm `latest`).
**Wire contract:** `wayland-desktop-core` **1.12** — 52 events, 23 commands,
161 fixtures, 3 JSON Schemas.
**Written:** 2026-08-08, against Desktop `app@0.11.18`.

Everything in §2 was measured against a local checkout of
`FerroxLabs/wayland` at `app@0.11.18` on the date above. Re-measure before
acting if that tree has moved.

---

## 0. TL;DR — the shortest correct upgrade

1. Bump `DEFAULT_WCORE_VERSION` in
   `app/scripts/prepareWaylandCore.js` from `'v0.12.25'` to `'v0.12.26'`,
   and refresh the pinned SHA-256 entries (§1).
2. **Read §2 before shipping.** Desktop currently handles **33 of Core's 52
   event types**. The other 19 hit the `default:` arm at
   `app/src/process/agent/wcore/index.ts:1152` and are dropped with a
   `console.warn`. **17 of the 19 are `criticality: "safety"`** — a class the
   contract defines as *must not be silently discarded*.
3. Do the §3 work in order. Steps 3.1 and 3.2 are the ones that turn a version
   bump into an actual feature release.

Nothing in 0.12.26 **breaks** Desktop's existing 33 handlers. The upgrade is
safe to ship as a pure bump. It just leaves most of the release's new surface
invisible to your users.

---

## 1. The mechanical bump

### 1.1 Version pin

`app/scripts/prepareWaylandCore.js:187`

```js
const DEFAULT_WCORE_VERSION = 'v0.12.26';
```

The comment above it is right and should stay: Desktop pins a tag rather than
tracking `latest`, so a release cut mid-CI cannot drift in.

### 1.2 Checksums

`prepareWaylandCore.js` refuses to extract an archive whose SHA-256 is not in
`SHASUMS_FILE` (it throws "Cannot verify bundled wayland-core integrity
(supply-chain guard)"). Pull the new sums from the release:

```bash
gh release download v0.12.26 -R FerroxLabs/wayland-core \
  -p 'wayland-core-checksums.txt' -D /tmp
```

Six targets: `x86_64`/`aarch64` × `unknown-linux-gnu`, `apple-darwin`,
`pc-windows-msvc`.

### 1.3 Optional but recommended — verify provenance

Every archive carries a keyless Sigstore build-provenance attestation:

```bash
gh attestation verify wayland-core-v0.12.26-<target>.tar.gz \
  --repo FerroxLabs/wayland-core
```

Core's own `self-update` does this and **fails closed** if `gh` is absent.
Desktop's bundler currently checks the checksum only; adding the attestation
check is a cheap upgrade to the supply-chain story you already advertise.

### 1.4 The contract bundle is a release asset

New in this release — you no longer have to vendor fixtures out of the Core
repo:

```bash
gh release download v0.12.26 -R FerroxLabs/wayland-core \
  -p 'wayland-core-v0.12.26-desktop-contract-v1.tar.gz'
```

Unpacks to `desktop/v1/{manifest.json,events/,commands/,compat/,adversarial/,schema/,types/}`.
`manifest.json` is the machine-readable index: every event and command with its
`criticality`, its `capability` gate, and its correlation key. Wire it into
Desktop's test suite and the drift in §2 becomes impossible to reintroduce.

## 2. The gap, measured

Core 0.12.26 emits **52** event types. Desktop's switch in
`app/src/process/agent/wcore/index.ts` handles **33**. The remaining **19**
reach:

```js
default: {
  const unknownEvent = event as { type?: unknown };
  const typeStr = typeof unknownEvent.type === 'string' ? unknownEvent.type : '<non-string>';
  console.warn(`[WCoreAgent] unknown event type "${typeStr}" - dropping`, event);
  break;
}
```

Verified absent from the whole of `app/src` — `grep` for each type name
returns zero hits, so these are unhandled rather than handled elsewhere.

### What each dropped family costs a Desktop user

- **`workflow_*` (3, safety).** A ForgeFlows run produces started / per-node /
  finished frames with `run_id` + `sequence` correlation. Desktop shows
  nothing: a workflow runs to completion and the UI never acknowledges it
  started. This is the largest single visible feature gap.
- **`session_recovery_*` + `turn_recovery_lifecycle` (4, safety).** Core can
  now recover an interrupted turn and tells the host how. Without these
  handlers Desktop cannot offer resume-after-crash even though the engine
  underneath supports it — the feature exists and is unreachable from the app.
- **`goal_*` (3).** Durable Goals are the flagship of this release. Desktop
  can neither render a Goal nor explain a refused Goal control.
- **`execution_policy` (safety).** The *effective* execution policy, with a
  monotonic `revision`. Desktop shows the mode the user picked; this frame is
  what the engine is actually enforcing after floors and overrides. When they
  disagree, today the UI is the one that's wrong.
- **`budget_grant_result` (safety).** Desktop already handles
  `budget_exceeded`, so it can show the wall — but not the outcome of the
  `continue_with_budget` command it sends in response. The grant loop is
  half-wired.
- **`runtime_diagnostics_*` (2, safety).** The reply to
  `get_runtime_diagnostics`. Send the command today and nothing comes back
  through the UI.
- **`mcp_removal_result` (safety).** `remove_mcp_server` completes silently.
- **`provider_failover_receipt` (safety).** The user is not told their turn
  was served by a different provider than the one they selected.
- **`anvil_receipt` / `anvil_receipt_invalidated` (2, safety).** Anvil's
  verified-vs-unverified receipt is the whole point of the gated forge.
  `publication_bound` capability — see §4.
- **`unknown_tool_effect_resolved` (safety).** The operator resolution of a
  tool whose effect Core could not determine.

### Two `ready`-frame details that will bite

1. **`session_persistence` has three values**, not two:
   `"durable"`, `"journaled_without_replay"`, and the degraded case. A session
   reported as `journaled_without_replay` is being written but **cannot be
   replayed** — the user's crash-recovery protection is off and Core is saying
   so explicitly rather than letting you assume otherwise. Desktop should
   surface this; there is a fixture for it at
   `compat/events/ready.journaled-without-replay.json`.
2. **Do not assert on `ready.version` against the fixture.** The fixture value
   is a frozen literal (`"0.12.25"`, hardcoded in
   `crates/wcore-protocol/src/contract/spec.rs`) so the corpus stays
   byte-stable across version bumps. At runtime the field carries the real
   binary version. Match on `contract.major`/`contract.minor` instead — that
   is what negotiation is for.

## 3. Recommended work, in order

### 3.1 Stop dropping safety frames silently — half a day

Before implementing a single new feature, change the `default:` arm so a
dropped **safety** frame is a visible failure rather than a `console.warn`.
The contract ships the criticality of every event in `manifest.json`; load it
and branch on it.

This is worth doing first because it converts "we didn't know" into a test
failure, permanently. It is also the thing that would have caught this gap
when it was 3 events instead of 19.

### 3.2 Wire the workflow and goal families — the visible release

`workflow_*` and `goal_*` (6 events, 5 goal commands) are what makes 0.12.26
feel like a new product in Desktop rather than a version number. Both are
sequence-correlated and both have adversarial fixtures covering the failure
shapes you must not accept:

- `adversarial/workflow/{sequence-gap,duplicate-conflict,duplicate-identical,after-terminal,conflicting-node-terminal,child-sequence-gap,child-duplicate-conflict,valid-lifecycle}.jsonl`
- `adversarial/recovery/{cursor-gap,cursor-digest-mismatch,state-digest-conflict,valid-replay,version-mismatch}.jsonl`

Each `valid-*.jsonl` is a positive control. Run both directions: a reducer
that rejects everything passes the negative fixtures and proves nothing.

### 3.3 Close the half-wired loops — small, high value

`budget_grant_result`, `mcp_removal_result`, `runtime_diagnostics_*`. In each
case Desktop already sends the command; it just never renders the answer.
These are three small handlers that finish features already shipped.

### 3.4 Surface the truth frames

`execution_policy` and the `session_persistence` degrade. Both are cases where
Desktop currently shows the user something more optimistic than what the
engine is doing. Neither is hard; both matter more than their size suggests.

### 3.5 Adopt contract negotiation

Core declares `contract_negotiation: "available"` and ships its capability map
inside every `ready` frame under `contract.capabilities`. Values are
`"available"`, `"shape_only"` or `"publication_bound"`. Gate Desktop's UI on
that map instead of on the Core version string — then a Core that ships a
capability early, or holds one back, is handled by construction.

### 3.6 Run the corpus in Desktop CI

Point a test at the unpacked contract bundle: every `events/*.json` must parse
into Desktop's typed reader, every `commands/*.json` must round-trip, every
`adversarial/**` file must be rejected, and every `compat/**` file must be
accepted. 161 fixtures, no Core checkout required. `manifest.json` carries
`fixture_digest` and `schema_digest` so you can detect a drifted bundle.

## 4. Capability semantics you need to get right

From `contract.capabilities` in the `ready` frame:

| Value | Meaning |
|---|---|
| `available` | Fully modelled. Fixtures are exhaustive; treat the event as a stable API. |
| `shape_only` | The frame's *shape* is contract-stable, but its payload semantics are not yet frozen. Render it; do not build irreversible logic on the payload. Currently: `browser_events`, `cua_events`, `plugin_events`. |
| `publication_bound` | Emitted only when the underlying feature actually publishes. `anvil_receipts` is the one. Absence is not an error — it means nothing was published, not that the capability is missing. |

Sub-contracts carry independent versions, in `manifest.json` under
`subcontracts`: `anvil_receipts 1.0`, `durable_child 1.0`,
`execution_policy 1.0`, `operator_tool_effect_resolution 1.0`,
`runtime_diagnostics 1.0`, `semantic_failover_receipts 1.0`,
`turn_recovery 1.0`, `workflow_lifecycle 1.0`. Version-check each family
separately; they will not move in lockstep.

Three adversarial reducers are declared **deferred** in
`contracts/desktop/v1/DEFERRED.md` — `ordinary_turn_tool_replay_reducer`,
`anvil_desktop_replay_reducer`, `anvil_persistent_mutation_watcher`. They are
named so Desktop knows the corpus does not cover them, rather than assuming it
does.

## 5. Behaviour changes that reach the Desktop user

Not protocol changes — product changes Desktop should account for in UX and
docs.

| Change | Desktop impact |
|---|---|
| **Plaintext credential fallback removed** | A host with no secure store now **refuses to save** rather than writing cleartext. Desktop supplies its own store through the ladder's host tier — verify that path end to end on a fresh machine, including a locked keychain. |
| **Three surfaces stopped reporting a locked token store as "signed out"** | If Desktop mirrored that wording, it is now wrong in the opposite direction. |
| **Durable sessions degrade explicitly and report why** | New user-visible state. See §2's `session_persistence` note. |
| **`--dangerously-skip-permissions` split into two tiers** | If Desktop passes the old flag anywhere, it no longer implies sandbox bypass. Check the launch argv. |
| **Read-only mode actually enforces** | Writes that previously slipped through under `read_only` now fail. Desktop error surfaces should say so cleanly. |
| **Untrusted project config can no longer raise `max_tokens` / `max_turns`** | A repo-level config that used to widen limits is now clamped. |
| **A project `[memory]` block cannot defeat a global memory opt-out** | Desktop's memory toggle is now authoritative. |
| **MCP servers are usable again** | Every MCP server was previously unusable — the model was never told a hydrated tool was callable. Both `ToolSearch` defects the Desktop lane filed are fixed. Re-run Desktop's MCP gate; it has not been exercised against a working Core. |
| **Windows: 140 ms → 68 ms per op at 24-way** | Desktop's Windows spawn paths get materially faster. Worth re-measuring any timeout Desktop tuned around the old number. |
| **Voice is opt-in on Linux** | If Desktop ships a Linux build assuming voice, gate on the capability, not the platform. |

## 6. Known Core-side items relevant to Desktop

Honest list; none blocks the bump.

- **`ready.session_id` can serialize as JSON `null`** in a degraded frame, and
  two `pub` emitters can in principle produce a schema-invalid `ready`. Filed
  Core-side. Desktop should treat `session_id` as nullable on `ready` until
  that lands.
- **Recursive-parent filtering for `Grep`/`Glob`** is not yet uniform: a
  deny-listed *target* is refused, a deny-listed *parent* is not filtered
  per entry. If Desktop exposes search over arbitrary roots, keep your own
  boundary.
- **Swarm workspace reservation over-reserves** — 8 GiB per worker plus
  512 MiB regardless of repository size, so a 4-worker dispatch needs 32.5 GiB
  free. If Desktop drives swarm dispatch, surface a clear error rather than a
  generic failure. Measured reservation lands in 0.12.27.
- **`#943`** — a nested `cmd /c` on Windows gains one stray trailing `"` in
  captured stdout. Exit code and execution are correct; only the captured text
  is affected. If Desktop parses Bash output strictly, be tolerant of a
  trailing quote on that shape until 0.12.27.

## 7. Verification checklist before Desktop ships

- [ ] `DEFAULT_WCORE_VERSION` = `v0.12.26`; checksums refreshed for all six targets.
- [ ] Fresh-machine launch on macOS, Windows and Linux — `ready` received, `contract.minor` = 12.
- [ ] Credential save works on a host with a secure store, and **fails visibly** on one without.
- [ ] MCP: add a server, use a tool, remove it. All three succeed and the UI reflects each.
- [ ] Unknown-event `default:` arm no longer silently swallows a safety frame (§3.1).
- [ ] Contract corpus test green: 161 fixtures, positive and adversarial both directions.
- [ ] A workflow run renders start → nodes → finish (once §3.2 lands).
- [ ] Windows: a Bash tool call returns stdout (this was #942; re-verify on Desktop's own path).
