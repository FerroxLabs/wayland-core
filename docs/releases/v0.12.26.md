# Wayland Core v0.12.26

**Stable — 2026-08-08.** GitHub **Latest**; npm dist-tag **`latest`**.

```bash
npm install -g @ferroxlabs/wayland-core
wayland-core --version        # 0.12.26
```

Already installed? `wayland-core self-update` verifies the release
attestation before it replaces the binary, and fails closed if it cannot.

---

## The short version

Twenty-six days. **2,918 commits** — 250 `feat`, 629 `fix`, 519 `test`,
740 `docs`. **5,506 files** changed, **1.07 million** lines added. It is by a
wide margin the largest release in the project's history, and it is the one
that turns Wayland Core from a very good agent CLI into an engine you can
hand a multi-day job and walk away from.

The organising idea for the whole cycle was a single sentence:

> **Nothing lies to the user, and nothing loses their data.**

Everything below is downstream of that. Work that survives a crash. Delivery
you can audit. Costs you can query. Guarantees that are measured against the
real platform rather than assumed. Capabilities that advertise themselves only
when they are genuinely live.

## Ten things that are new

### 1. Goals that outlive the process

A **durable Goal kernel** now sits under all five loop owners — Anvil,
Council, Crucible, ForgeFlows and Direct — with one canonical terminal
taxonomy lifted into `wcore-types` and a single transition driven from the
shipped binary. Kill the process mid-run and the Goal is still there, in
state, resumable.

Goals are first-class on the wire too: a typed Goal control command set on the
host protocol, `goal stream` for a live view, refusals rendered in the TUI,
and durable Goal state shown in the terminal. Fleet work rides a **durable
task ledger with an epoch fence** — dependencies are enforced at the durable
boundary, an agent releasing a claim must present its own epoch, and a
loop-owner claim carries a lease so a dead owner can never deadlock its Goal.

### 2. Run anywhere: a provider-neutral execution backend

`wayland-core backend` gives you one contract and four reference backends —
local, ssh, container and cloud. The cloud backend genuinely **creates, runs
and hibernates a machine**; a cancelled run writes a `Cancelled` receipt
rather than vanishing. Nodes carry attested attribution, an orphan scanner
sweeps what got left behind, and `receipt verify --against-backend` checks
*identity*, not just integrity.

### 3. A gateway you can operate

The channel gateway grew an **exactly-once delivery ledger**, an observable
drain state, a lifecycle machine, and a Windows-safe instance lock. A
single-owner inbound polling lease runs across all three `start_all` sites, so
the installed service outranks an ad-hoc session and the loser reacquires
cleanly instead of fighting.

The part operators will feel most: **abandoned deliveries are nameable,
acknowledgeable and re-sendable**, and they are exempt from compaction until
someone has actually looked at them. Deliveries whose outcome is unknown are
no longer re-sent to destinations that cannot dedupe. And
`gateway support-bundle` produces a redacted bundle proved clean by canary.

### 4. Ten channels, with native actions

Slack, Discord, Telegram, Matrix, MS Teams, Email, WhatsApp, Twilio, SMS and
the local channel — each now **declares its native action capability**, and a
cross-adapter conformance matrix (with five declared negative adapters) keeps
those declarations honest. `channel actions` prints the matrix and can gate a
deployment with `--require`.

Per-platform highlights: Slack `chat.update`/`chat.delete` plus a setup probe
and auth classifier; Discord edit/delete with configurable API and gateway
bases; Telegram edit/delete; Matrix `m.replace`, redaction, and a `/sync`
cursor that survives restarts; MS Teams activity PUT/DELETE and inbound
attachment parsing; Email TLS trust anchors and an IMAP poller that stops
discarding all but the largest message; a WhatsApp bridge behind an opt-in
backend seam.

Cron got the same treatment: the schedule is **leased** so exactly one process
fires it, every trigger type is reachable from the shipped binary, and
event/webhook/poll triggers now validate, persist and actually fire.

### 5. A persistent code index

`wayland-core index` — **build, status, search, verify**. An incremental
repomap index with git-respecting scope, WAL checkpointed after each refresh
so the reported size is steady-state, and explicit refusal of unknown store
schema versions. When semantic search is unavailable, `index status` says
`semantic status=unavailable` **with a reason**.

### 6. Backup, restore and rollback that hold under pressure

Full **backup archive, verify, restore and write-ahead journal**. Live SQLite
is captured *consistently* into the journal undo store. A **scoped operation
journal** records declared scope, absent-set and an exact reverse-apply — and
`migrate` is now rollback-able. Newer-schema archives are refused; older and
truncated ones are covered; unrestorable paths are refused before the first
write rather than halfway through it. A dead owner's restore is recovered
before occupancy and before a new journal is opened.

### 7. Bring your history with you

Typed, redacted, deterministic **migrate discovery**, with real importers for
**openclaw, grok and gemini-cli**. Every provenance record is bound to where
the bytes actually landed, imported content is genuinely written (and only
what was written is counted), and the quarantine index is written atomically.
The containment contract was measured at real import scale, not sampled.

### 8. Costs you can actually query

A **daily spend ceiling** with a config path and a durable store. Proactive
budget envelopes that **sub-allocate to delegated children**. A
**cache/compaction ledger** — session-scoped quality, invalidation, token
pressure and cost truth — wired into the engine and exposed through
`wayland-core cache` (report/list/show/verify).

Cost truth records its *source*, so a family-rate estimate is never
mistaken for spend. Totals roll up across sessions, because restart-fragmented
spend is invisible from inside any single one. Cost is attributed to the route
rather than the compat profile. Media billing covers TTS, all three vision
backends including `video_analyze`, every billable transcription call and the
`image` subcommand, with units and basis declared.

### 9. Memory you own

`memory.enabled = false` stops recording, full stop. A **memory activation
surface** lets you see and switch off exactly what memory is putting in your
prompt. `/memory why` and `/memory correct` show **what** each item says
rather than just its id, and recall provenance is exposed with operator
controls over it. The new `/usermodel` surface displays inferred beliefs
marked by origin, and adds a user-authored correction layer with render
precedence — your correction wins.

### 10. Voice, by default

Voice ships **default-on for macOS and Windows**, with barge-in made real:
killable playback, a wired interrupt and a live readiness gate. On Linux it is
a one-flag opt-in (`--features voice` plus the ALSA dev headers) so that the
stock binary starts on any host, ALSA installed or not — and the product
reports voice as *absent from the build* rather than as a broken device.

## Governed skills, plugins and MCP

**Skills.** Governed promotion, revocation and rollback on the shipped binary,
surfaced through `/skill govern` with journal events rendered. Rollback is now
atomic — stage, fsync, `rename(2)` — where it previously wrote your skills
directory file by file. Staging trees are never discovered as skills, session
catalogs are isolated, and revoked skills' router seeds are dropped at
hydration.

**Plugins.** Plugin approval became a **load-time gate rather than a prompt**.
Ten missing lifecycle verbs were added, `plugins.toml` is loaded from disk at
engine boot, and both shipped templates build clean against `cargo-generate`.

**MCP.** Every MCP server is now usable. The model was never being told that a
hydrated tool was callable — that is fixed, along with both `ToolSearch`
defects the Desktop lane reported. Plus: a runtime removal lifecycle,
resource-only server support, readiness bound to launch context and modelled
as *executable* readiness, serialized connection lifecycle, tools exposed
before provider turns, and the CLI awaiting MCP before the first turn.

## Security

Wayland Core runs with your keys, in your repo, against your infrastructure.
This release spent a large fraction of its effort making that boundary
airtight.

- **The credential deny-list is enforced on every read tool.** `Read` already
  refused `/etc/shadow` and `~/.ssh/id_rsa`; `Grep`, `Glob` and `Bash` now
  consult the same list — and `Grep` returns matched line *content*, so this
  matters. Four paths closed: `Read` of the per-process procfs subtree, `Grep`
  and `Glob` at a deny-listed target, and `Bash` running
  `cat /proc/self/environ`. `~/.git-credentials` joins the list. The check
  lives in one shared `validate_search_root` so a fifth tool cannot repeat the
  pattern. Every guard is mutation-confirmed, and every refusal test is paired
  with a negative control — a guard that refuses *everything* cannot pass.
- **A fail-closed credential ladder** replaces the plaintext fallback
  completely. Upper tiers are trait objects, so a host can supply its own
  store. OAuth tokens moved into the ladder.
- **Spanned keyring writes are serialized across processes** and anchored at
  `wayland_config_dir`, closing a window where two concurrent writers could
  splice two secrets together.
- **Sandbox bypass cannot be activated remotely** — not by configuration, not
  by environment, only by an explicit local Dangerous launch. The old
  `--dangerously-skip-permissions` split into two named tiers so the superset
  is visible in the flag itself.
- **Reserved authority**: nine closed actions, one principal, a root that
  fails closed. Session authority isolated, cancel authority sealed, expiry
  enforced, sandbox runtimes scoped per session.
- **Trust is bound to executable state**, not declared state. A managed
  execution floor is wired with a runtime approval-snapshot ratchet.
- Every value crossing the ssh boundary is quoted; the REST bypass of role
  gating is closed; imported executable content is classified and contained
  under the GHSA-8r7g contract with the execute bit stripped and reported.
- Credential scrubbing became a **type invariant** rather than a call-site
  habit — including credentials embedded in free-form plan details. OCR secret
  scanning covers contextual and fragmented evidence in the CUA path.
- RUSTSEC-2026-0222 patched (wasmtime 36.0.12 → 36.0.13); quick-xml
  suppressions dropped and closed at source; the dependency policy is now
  actually executed on every run.

### Privacy

A bare `[memory]` block in a cloned repo can no longer undo a global opt-out,
and a refused project opt-in warns rather than passing silently. `set_memory_api`
refuses when memory is off, closing the host bypass. The evidence bundle is
redacted and refused whole if any projection leaks.

## Durability

- **Crash-complete session persistence**, interrupted turn state sealed, tool
  effects made crash-durable.
- `wayland-core session` — an operator surface with real verbs over the
  session substrate.
- Journal: storage authority gaps closed, fail-closed on uncertain storage,
  replay publication races closed, snapshot authority hardened, durable stream
  events retained. Checksum material is hashed **as written** rather than as a
  re-encoding, and pre-fix journals stay recoverable without loosening the
  checksum. Compactions publish with a rename that can replace an open file,
  and the writer lock no longer blocks Windows readers.
- Each engine decides whether it can seal. A host that cannot seal journals
  *without* the seal, and the wire **names** the journaled-without-replay
  session rather than letting you assume otherwise.
- Durable sessions degrade explicitly at startup when no secure store exists,
  and report **why** — and operators can *require* them instead of accepting
  the degrade.

## Platforms

### Windows

Windows took the single largest share of this release, and it shows.

- The swarm workspace lifecycle is fixed at the root. The
  workspace-accounting walk no longer demands `DELETE` on a read-only scan —
  a live `git` process inside a checkout used to kill a healthy worker and
  report the wrong cause. Destructive cleanup now retries a bounded,
  errno-gated sharing violation.
- **Performance: 140 ms → 68 ms per op at 24-way concurrency**, with the
  AppContainer probe down from 3,381 ms to 1,188 ms. The probe came off the
  ready path and off the tokio worker, profile RPCs came out of the global
  lock, a successful probe is shared across processes, and a transient probe
  is retried rather than refused — with a cause attached when it is.
- Path handling settled: `\\?\` verbatim prefixes stripped from
  `lpCurrentDirectory`, swarm roots de-verbatimized, one representation for
  the transaction root and its authorities, `atomic_write` past `MAX_PATH`,
  and five divergent UNC checks consolidated onto one module.
- **Log rotation and worktree reclaim work.** The daemon survives its session,
  the scheduled task recovers a hard-killed gateway, and
  `CTRL_BREAK`/`CTRL_C_EVENT` handler control fires correctly.
- AppContainer: execution identities isolated, ACL lease persistence hardened,
  stale and 0-byte leases reclaimed instead of wedging, `fs_read_deny` made a
  real control via protected-DACL removal, child cwd bound to the retained
  authority.
- Windows clippy `-D warnings` is clear across all newly reachable code.

### macOS

One spelling for every path that crosses a boundary. A finished root is no
longer misread as a containment failure. Symlinked ancestors resolve, so macOS
temp paths are ingestible. Root-churn is discriminated by event **kind** — a
blanket root drop had been blinding macOS file watching. `kinfo_proc` is read
by measured offset with a `p_pid` self-check. The acoustic voice suite runs on
a real self-hosted runner that can actually record.

### Linux

Process trees are owned and reaped, cgroup authority is enforced, and the
cleanup reaper is back in the integration path. The default binary starts on a
stock host with no audio stack present, and a build-time shared-library gate
now reads `DT_NEEDED` against an explicit allowlist on **both** Linux targets
before packaging — with a self-test proving the gate rejects what it claims to
reject.

## Supply chain and release integrity

- **A signed release manifest** with a role-scoped trust root and a closed
  four-state ledger, published by `release.yml` and drilled end to end.
- **A deterministic CycloneDX SBOM** generated from the locked graph, with
  byte-determinism enforced in CI.
- The downloaded archive is **bound to the digest the manifest signed**, and
  the shipped updater makes an ordered, fail-closed update decision.
- **Rollback rehearsal and a state-separation drill run in CI** on every
  release-bearing change.
- Release archives carry keyless **Sigstore build-provenance attestations**;
  npm packages publish with `--provenance`. There is no long-lived signing key
  to rotate.
- The builder's source path is no longer baked into the release binary; full
  source identity is embedded; `--locked` builds are restored.

## CLI and TUI

Quiet default startup, terminated headless stdout, de-jargoned `--help`.
Diagnostics logging is created with the first record rather than at startup,
is bounded, and announces its fallback. Danger tiers are named so the superset
is visible in the flag.

In the TUI: the onboarding card no longer appears over a configured session
and no longer eats your first message; `SPACE` is prose, not an accelerator,
and the shortcut-vs-prose rule is settled so documented shortcuts keep
working; formatters read what tools actually emit and never invent a value;
`raw_text` no longer trims; a rebound provider and model are mirrored onto the
status bar; composer images are ingested; and durable-Goal control and state
are reachable from the terminal.

## Evidence and certification

The `wcore-eval` and scenario crates account for 98 user-facing commits on
their own. What they buy you is a release whose claims are checkable.

- **Verifiable receipts** built from real runs, projected into formats,
  redacted for reporting, and bound to live fixtures and exact artifacts.
  Authoritative receipts are required; hollow and ambiguous evidence is
  rejected; a signed receipt cannot be overwritten, only superseded.
- A **certification contract, severity rubric and skip taxonomy**, with all 60
  Phase 28 findings adjudicated and the certification receipt signed and
  verified two independent ways.
- A **soak harness with VOID rules and a positive control behind every
  observable** — an observable with nothing proving it can move is not an
  observable.
- Drift detection, a signed drift ledger and disclosed supersession.
- A **scorecard** with an asymmetric verifier and the `wayland-scorecard`
  binary, reading its surface inventory off the shipped binary so maturity is
  a measured truth rather than a claim.
- A **setup-to-recovery journey driver** and receipt verifier running on all
  three platforms, with the adapter set an explicit parameter and repeats
  graded by delivery identity rather than message body.

Some of the most valuable work in this release was in the test harness itself.
A deleted failing test no longer satisfies the merge gate. Bare `cargo test`
can no longer produce a vacuous green — an anti-vacuity linter requires
nextest, `--no-run`, or an explicit annotation. Zero tests is no longer
reported as green on any leg; each asserts it produced signal. Two gates that
could never *pass* were found and fixed. Retried-away failures keep their
output. The result is a suite whose green means something.

## Upgrading

Most installs are a drop-in. These are the changes that can be felt, each
with the reason behind it.

| What changed | What it means for you |
|---|---|
| `--dangerously-skip-permissions` split into two tiers | The old flag silently included sandbox bypass. If you want that, ask for it by name: `--dangerously-skip-permissions-and-sandbox`. |
| Plaintext credential fallback removed | A host with no secure store now refuses to save rather than writing cleartext. Set up a store, or use the ladder's host-supplied tier. |
| `[default] read_only` actually enforces | It was advisory in paths that mattered. If you relied on writes succeeding under `read_only`, they now correctly do not. |
| Project config can no longer raise `max_tokens` / `max_turns` | An untrusted repo cannot widen the limits you set. Raise them in your own config. |
| The egress master switch is operator-owned | A project can no longer negotiate it. |
| A project `[memory]` block cannot defeat a global memory opt-out | Cloning a repo can no longer silently re-enable memory. |
| Skills lifecycle opt-out no longer fails open for untrusted projects | |
| `voice` is opt-in on Linux (default-on for macOS and Windows) | Build with `--features voice` plus `libasound2-dev` / `alsa-lib-devel`. |
| **Workspace trust gates authority-expanding project config** | Read this one if you write `.wayland-core.toml`. `[profiles.*]`, `[mcp.servers.*]`, `[providers.*]`, hooks, `env_passthrough` and the sandbox keys are stripped from an **untrusted** workspace, so a cloned repo cannot grant itself an MCP server or a provider. Trust a workspace once with `--trust-workspace`. |

**That last row is a breaking change** for any consumer that writes project
config, and it deserves to be called one rather than left for you to discover.

It was also, until this release, unexplainable. `--profile p` in an untrusted
workspace reported `Profile 'p' not found in config` — for a profile that was
present in a file Core had just parsed and then discarded on the trust
decision. The only true account of it was a `tracing::warn!` invisible at
default verbosity. The refusal now names the trust decision and the remedy. A
profile that genuinely was never written still reads as absent, so the new
message cannot send you chasing `--trust-workspace` over a typo. Found and
reported by the Wayland Desktop lane, whose per-chat generated workspace hit
exactly this.

### Delivery guarantees, stated precisely

Worth reading if you build on channel delivery. These are measured against the
real platforms rather than assumed, and the product now enforces exactly what
it states:

- **Matrix — exactly-once, below the message length cap.** Above the cap the
  transport splits and the guarantee does not survive; Wayland Core asks the
  question per message rather than assuming.
- **Discord — at-most-once.** The dedup token both adapters send is now
  genuinely used rather than discarded, but the platform's own guarantee is
  at-most-once.
- **Slack — at-most-once.** `slack.com` ignores the `Idempotency-Key` header.
- **Browser and CUA capabilities advertise on liveness, not linkage.** They
  appear when they can actually run.
- `is_concurrency_safe` is now backed by the behaviour it declares across all
  45 declarations.

## Next up in 0.12.27

Tracked, scoped and already understood:

- **Swarm workspace reservation becomes measured.** Dispatching N workers
  currently reserves a flat 8 GiB each plus a 512 MiB margin regardless of
  repository size. The fix separates "how many workspaces exist" from "how
  many am I creating" — a measured-reservation patch was written for this
  release and held back because it charged its floor to retained workspaces
  too. Right answer, wrong arithmetic; landing properly in 0.12.27.
- **Recursive-parent filtering for `Grep`/`Glob`.** Deny-listed targets are
  refused today; per-entry filtering under a recursive parent needs uniform
  support across the `rg`/`grep`/`findstr` backends so the boundary does not
  depend on which binary happens to be installed.
- Two sibling Windows read-walks still request `DELETE`; the delete
  disposition will carry a structured errno so a sharing violation there is
  retryable.
- `#943` — the stray trailing quote on a nested `cmd /c`.
- **A workspace whose executable surface contains a symlink cannot be
  trusted.** The fingerprint fails closed on symlinks under
  `.wayland-core/skills` and `.wayland-core/commands`, so a host that composes
  a workspace by linking in its own assets cannot obtain trust for it, and
  `--trust-workspace` does not help — the fingerprint refuses before trust is
  consulted. The workaround today is to write those files as regular files, not
  links, which is also the stronger position: a symlink lets the fingerprint
  and the executed content diverge, while a copy means the surface that was
  trusted is the surface that runs. 0.12.27 will fingerprint a link's resolved
  target when it stays inside a boundary Core can verify for itself, with the
  escape cases (link out of the workspace, link cycles, links to devices or
  FIFOs) pinned first. Reported by the Wayland Desktop lane.
- The `Windows live-acceptance` gate gets a real baseline so it can
  distinguish a regression from the status quo.
- **`corpus_fan_out` reddens the macOS CI leg intermittently.** A test-harness
  defect, not a product one: `tests/support/pty.rs` panics outright when a
  write to the PTY master returns `EIO` because the child has already exited,
  which on macOS is a legitimate race on the shutdown path. It affects how
  reliably a release can be certified rather than anything a user runs, and
  the fix is to tolerate `EIO` only where the child is expected to be gone —
  not to swallow write errors generally, which would make every drive step
  vacuous.
- `deny.toml` suppressions carry a dated expiry of 2026-09-02 and will be
  closed at source before it.

The full list lives on the issue tracker.
